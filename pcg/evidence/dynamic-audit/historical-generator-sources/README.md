# 历史生成器源与执行哈希

正式 `dynamic-search-v3` / `dynamic-evaluation-v1` 使用 `b442bb25114b4dad0aded15634489c12324ebaf0f1ed168e74d704dc111f3cb5.py`；正式 `region-sky-v1` 使用 `3ed9898d81a0c9d43fbf5aa3aa132fba56b9af0b12a42864d86c2e90cd1f2687.py`。

这些文件在交付整理时从可逆代码差异重建，完整SHA256逐字节匹配运行前 `*.execution.json` 记录的源哈希；不是另跑出来的新版本，也没有覆盖历史输入输出。其余正式执行账本列出的代码文件与当前源哈希一致。归档的7个正式批次源均可定位；当前生成器另修复了提案/实际能力合同和登船跳元数据。

`index.json` 也保留两次早期诊断版本的4个未匹配源条目。它们的完整旧生成器源未在编辑前保存，不能声称按旧seed精确再生成；原始输入/输出/日志仍保留，可用冻结worker重放原物理输入。正式结论不取自这两次诊断批次。

复现正式历史算法时，把对应文件作为 `prototype/dynamic/generators.py` 放入独立副本，核对其余执行账本源与引擎版本；不要覆盖当前工作副本或历史结果目录。
