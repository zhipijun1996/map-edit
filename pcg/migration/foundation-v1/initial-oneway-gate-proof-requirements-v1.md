# 初始单向机关接口：证据要求（迁移审查用）

依据根 `MAP_FOUNDATION.md` §3.3、§7。本文记录认证要求，不声明现有样品已经满足，也不新增 Map 生成器。

## 权限和作用域

- Port 的 INPUT/OUTPUT/INOUT 是地图初始状态下的方向权限。必须写明门的初态、控制风铃所在一侧、实际绑定和能力条件；同一机关开门后可能双向，不反推初始双向。
- “门初始关闭”不能独自证明单向。允许方向需要真实动作路线；禁止方向需要真实阻挡及有限反例。仅未找到反向脚本不是封口或不可达证明。
- 普通几何有向 Route 和机关初始权限分别记录；未认证方向保持 UNKNOWN。通过该机关才能取得的能力不能作为初始允许方向的前提。

## 正向见证与反向反例

1. 冻结 Module 内容版本、全部 Port、门和风铃的真实几何、门初态/权限、动作策略、能力/资源与物理源码。
2. 在现有 Harness 中，从允许侧外部邻接试件出发，连续进入、触发机关、全身越过接口并稳定离开；不在接缝补平台、恢复资源或重置门。射击必须表现为真实弹丸命中和门状态变化。
3. 从禁止侧分别测试走路、普通跳跃、反冲、提前开门、越顶/绕底及对控制物的可见射线；按预登记预算和原反例政策判断。撞墙/少量扣血/标记权限不能替代不可通行的实体证据。
4. 短时门按实际弹丸飞行、人物位移、全身通过和防夹记录。若窗口已过，恢复/返回必须真实验证；关闭前跨过中心点不足以证明身体清门。
5. 一个风铃绑定两门时，验证初始一开一关、每次真实触发后的互斥状态，以及原有防夹语义。不能只从输入声明推断两个门的实际碰撞状态。

## 部分连接、后续状态和留出

- 独立验证所开放的封口配置；封闭未用口后，保留 Route 仍真实可行，封口不产生新通路。通过一个配置不开放全部子集。
- 若核心玩法允许开门后折返，记录为完整特殊结构的后续状态路线；通用初始图不把未开门的反向连接视为有效。
- 校准、独立留出、相位/瞄准扰动与预算沿用原质量门槛。看过留出的候选不能通过换名字/seed再次获得“独立留出”；观测器修正优先对原 raw 作只读重分析。
- 证据应包含初态、原始动作/输入、逐帧门状态/碰撞/人物身体轨迹、源码绑定、正反向及恢复结果、反例搜索范围和未覆盖项。有限搜索不声称数学证明。

## 当前工具边界

现有迁移物理工具提供真实动作、全身 Port 过界、连续接缝、能力/资源和固定廉价反例；专门针对“初始单向核心门”的完整配置认证尚需按实际候选补齐。不能因为已有局部接缝通过，就自动签署初始单向权限或所有封口组合。该缺口不应被补成虚假的通过字段。
