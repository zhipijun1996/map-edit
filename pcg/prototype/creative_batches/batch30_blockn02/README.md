## 真正发现的矛盾

v1误把静铃放到 `[704,560]`。原角色真实跳高比先前坐标猜测大，左下射弹从上方穿过P1台面才能去铃。高路线c0第273帧真实 `projectile_impact=[715.48,531.04]`，击中P1上表面，P2没启动。低路跳起又落在原停着的P2上，随后跨不到过远的低岸。8/8失败，原件保留。

v2恢复原草图铃 `[560,476]`，并将P2停位移到玩家后方 `[720,416]`，期望避免它只当免费静态踏脚；终点 `[1152,288]`，原线性travel0.65s。高路从P1先实走过静台右缘再跳射。低路则不多跳，穿P2下面射击反冲；低岸左沿改为1056。

低路线4/4真实到奖，1枪1跳，333–359tick；原P1真实承载176–192帧，包含真实中性承载，P2未参与。**这只是一条低路原型，不能算三口分叉。**

高路线仍4/4失败：第281帧真实 `projectile_impact=[810.89,420.27]`，命中停着P2的右侧，位于原弹丸碰撞半径内；原控制铃依然没被击中。没有 `bell_open` / `carrier_toggle`。低线通过不能掩盖A→B缺失，也不能降低机关目的门槛来入库。

P1自动相位只使用原 `platform_phase` 可见窗口观察进场；本轮8+8为原名义phase0.6的core检查。因为高核心失败，随机相位筛选、原regular、独立留出、廉价绕法和同世界恢复都 **NOT_RUN**；没有把phase0.6当作全相位验证。

下一修订可让静铃位于P2静止右缘808与实测射点约907之间，同时高于P1面534，例如 `[832,476]`。它是**未执行的提案**，需要重新注册与实际验证，尤其还要搜索静台直接到高岸、P1跳高岸、岸上预启后省P1等反例。当前不偷跑第三规则。

## 与已有内容的区别尚未成立

旧 `carrier-rendezvous` 有37.45秒影片、7秒平台停驻及最多18秒入口等待，被模型以节奏暂扣，但技术记录保留。本案试图用主动启动第二台减少被动等候，并在同一初始乘行中分出低/高后续路线；它也明显组合C05路线选择与D05追接。两个平台本身不算新家族，而此处主动追接没有实际成立，所以不宣称体验创新已经验证。

实际弹道遮挡已反哺记录：不能只用角色中心猜静铃坐标，必须读原枪口、真实弹丸impact与该帧完整运动台。不能持续生产同类被台面挡枪的参数版，也不能把只有低出口的原型当作分流成功。
