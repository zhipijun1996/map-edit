# D03：有限借火与敌人死亡后的替代动作

历史工作版本为 `rules_v5.py`，当前最终冻结入口见下文 `api_v1.py` / `rules_v8.py`，两个显式空间需求、四个端口、每接口七条程序。原EnemyActor/3HP/真实命中回充/碰撞/落地资源，未修改共享Harness、核心物理或候选库。此处是有核心表现但尚未过完整门槛的原型，不是已入库候选。

## 已真实表现的核心

- A→B、A→C各用一次跳跃、两次实际空中敌命中和第三枪反冲，取得对应12币；敌人3HP→1HP，没有中途落地回充。
- 两条分段路线用3次跳跃/3次射击、两次真实中间落地，不借敌人命中；保留敌人3HP。副目标不因敌人死亡消失。
- 同一世界先到东岸取12币，再向中间返回时射杀最后1HP，改走左侧分段落地路线取得另12币。原型清洁见证约8秒，状态不重建。
- 另有敌人存活也可通过的主出口，以及上述两宝后离开的连续清洁见证。主路不是本玩法的新颖性计数。

第一接口与第二接口具有不同的东口前沿和高差，第二接口东侧低接收岸增宽；西口保持同一外接锚，属于非统一缩放/非纯seed的空间适配。

`main_v1.tscn`仅增加真实HP的世界标签和HUD读数，原actor/资源/伤害不变。Godot `--check-only`通过。`pcg/results/workshop-batch30-d03-counter-v5/review_cases.json`给两条冻结清洁输入，可以由根的原 `workshop.record` 配此scene录制为**原型审阅**，不能由此晋升技术候选。

## 修订与实验

- 原始测量probe-v1/v2各4条：过高远岸失败；纯向下末枪确认两次真实命中可继续抬升。
- rules_v1：6条接口0，发现左高岸头顶碰撞、初始右走撞敌、回地后射杀太晚。
- rules_v2：6条，空中清敌解决接触伤害；左替代起跳点落在高岸正下方而失败。
- rules_v3：接口0七条clean、两接口14clean通过；84 mild暴露东替代首岸够不到及第二接口裕量不足。
- 经根协议v2授权v4/v5：v4轻斜末枪减少横向停滞、修两接口真实开口；11 changed clean/40mild仅第二接口东替代失败。v5只扩该接收岸，clean1+mild6全过；18 moderate保留上述6失败。
- 最后2条v5精确连续canonical通过；12条逐枪省略反例均未到相同目标。有限反例无成功不等于证明别无解法。

## 反例解释必须匹配外在目标

同目标还需包含 `required_rewards` 与有序 `via_ports`。敌人死亡恢复是要测试一个特定世界状态：省略清敌仍取两箱是合法的另一种状态策略，不推翻“死后仍能走”的见证。分段路的价值是保留敌人HP；用敌人走已知空中近路是另一种合法策略，不应相互误杀。空气近路若存在同样快且少消耗敌人资源的走法，才会反驳资源近路的设计假设。

不强迫玩家复现三枪序列。名义purpose验证当前发布程序的因果观测，原型不是所有合法策略的必要性证明。根统一counter分类必须区分这一点，特别是 `len(shots)>=3` 不应把同样消耗两次敌命中的合理两枪替代称为破坏玩法。
