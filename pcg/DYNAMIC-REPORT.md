# PCG-DYNAMIC-04：真实动态机关与区域输入生成

本轮把动作生成接到了游戏原有的移动平台、移动锯轮、宿主荆棘、伤害与段落回退组件，并加入区域约束编译器。浮岛已经有真实运行正例；蕈灯地穴的弹射蘑菇/孢子气流仍是未实现机制，执行入口会明确拒绝。正式游戏和 Map Notes 仓库未修改。

算法沿用 [前轮研究](COMPOSABLE-REPORT.md) 的动作语法与轨迹驱动几何，新增有限参数/相位等待策略搜索。这不是已经完成的完整 MAP-Elites、MCTS 或任意自然语言关卡设计器。实际趣味、苦痛之路级设计质量、正式 Runtime 成本均尚未证实。

## 可复现入口与来源

- 游戏运动/机关来源：`gunman-rush@12f6cb006d7119598e3235f4ca4f7323e4c9d092`。前轮已核对开发头 `54573a8e9400d790f58656efde2dd812cc00d8ba` 的相关运动源无变化；不把它冒称本轮运行版本。
- 引擎：Godot `4.7.2.stable.official.ed1daf0bf`，60 Hz。
- `prototype/dynamic/generators.py`：动作提案、真实参考轨迹布置接收面、荆棘 Cells、移动锯轮时机与载人平台参数。
- `prototype/dynamic/search_dynamic.py`：几何和有限时间窗口搜索；原始校准档案只按稳定出口归档，最终交付必须再经过 `evaluate_dynamic.py::purpose`。
- `prototype/dynamic/evaluate_dynamic.py`：真实动作词、连续空中动作、载人证据、留出初相位、输入扰动与较低成本替代策略。
- `prototype/dynamic/{regions,search_regions}.py`：区域 JSON 校验、实际几何转译、重新物理验证与扰动。
- `prototype/godot/{runner_v3,dynamic_context,main_v3}.gd`：正常 Node 调度、真实伤害提交与交互/输入回放。
- [独立源码与数据审查](research/dynamic-audit.md)、[区域字段说明](research/region-input.md)。原论文、实现、许可证研究仍见 [REPORT.md](REPORT.md) 和 [research/algorithms.md](research/algorithms.md)。

运行命令（输出目录不可已有同名物理结果）：

```sh
python3 prototype/dynamic/search_dynamic.py --words 4 --name dynamic-search-v3
python3 prototype/dynamic/evaluate_dynamic.py --name dynamic-evaluation-v1
python3 prototype/dynamic/search_regions.py \
  --region regions/sky_islands.research.json \
  --capabilities move,jump,double_jump,wall_climb,grapple,shot_recoil \
  --name region-sky-v1
python3 -m unittest discover -s prototype/dynamic -p 'test_*.py'
```

Python 依赖沿用前轮；必须先恢复 `source_provenance.json` 中的原游戏资源并使用指定引擎，不能用其他运动模型代替。新生成器不依赖完整预制 Module；动作构造规则和机关族仍由作者定义，不是完全从零学习设计语言。

正式批次所用生成器源另存 `evidence/dynamic-audit/historical-generator-sources`，其完整SHA匹配运行前账本；其余正式运行源与当前版本一致。早期两次诊断的旧生成器全文未保存，原始输入/输出仍保留，只承诺重放输入，不声称按旧seed再生成。当前代码修复元数据后不应覆盖旧正式目录。

## 真实机关与验收语义

V3 不再在 `physics_frame` 信号中提前手工推进动态角色。原模块时钟优先级 -200、移动平台 -100、研究输入 -10、原 Controller 0、锯轮/接触源 900、伤害政策 1000、观察 1100；UI 与 worker 使用相同调度。无伤成功要求完整身体无危险接触、无真实扣血、在真实出口支撑上稳定至少 6 帧且运动速度不超过 1 wu/s。

实际扣血与返回均走原政策，未用 `reset_at` 假装回退，也未改运动数值、能力次数或资源恢复规则。ENV 回退保留 HP 与模块时钟。伤害提交、最终扣血和危险接触独立记录；出生保护不构成无接触证明。

`results/dynamic-worker-v1` 的 7 个校准例证包括：真实平台零轴载人 155 帧、位移 300 wu、相对漂移 0；锯轮及荆棘分别导致 HP5→4、epoch 递增并返回 entry，clock 不倒退；伤害99致死而不回退；错误相位等待超时。UI 的真实键盘撞刺校准也验证 HP5→4，回退 clock 保持 0.966667s，继续10帧推进到1.133333s，无伤资格保持失败。

## 动态搜索与留出评价

正式搜索 `dynamic-search-v3`：16 个动作提案，14 个成功布置几何，146 条几何/时间策略，584 次校准物理运行，313 次无伤稳定出口，24 个校准档案条目；连同运动提案共 600 次物理运行，33.89s。271 次失败原因是 `real_damage`，失败保留。校准成功不是高质量模块数量。

最终评价独立检查动作目的，再在每族选3个，共12个。以下“通过”均要求目的动作词成立；移动平台还要求真实 `support_id=carrier`、零轴至少30帧、载人位移至少100wu和至少20帧平台速度大于20wu/s。没有把站在附近当搭乘。

| 研究挑战 | 留出初相位/静态基准 | 轻扰动 ±1帧/±2° | 中扰动 ±3帧/±6° |
| --- | ---: | ---: | ---: |
| 荆棘空域：重复墙跳+二段跳 | 3/3（静态） | 27/36 | 13/36 |
| 安全锚点等待后穿移动锯口 | 36/36 | 36/36 | 27/36 |
| 实际搭乘后用二段跳离船 | 25/36 | 30/36 | 21/36 |
| 实际搭乘后用反冲离船 | 36/36 | 36/36 | 34/36 |

动态族每模块抽取12个未用于校准的随机初相位。多对象输入按对象分别采样；本批正式候选每个只有一个动态对象，不能宣称已覆盖多机关联合相位空间。扰动试验另抽相位，所以二段跳平台轻扰动30/36高于基准25/36不能解释为噪声改善操作。以上是自动状态反馈策略，不是人的成功率。

删除选定的相位等待条件，保留相同几何/初相位和其他反馈，移动锯口通过19/36，两类平台均0/36。这只说明当前策略的等待有价值，并不证明其他玩家策略必须按此等待。

评价总703次物理运行，56.34s，含196次有限替代/动作遗漏反例。12个模块中4个发现更少能力或更少关键动作的通路：1个墙跳模块及3个反冲平台模块。交付 UI 会显示警示，不把它们签成“动作必要”；其余没有找到替代也不构成必要性证明。

族均值掩盖了两个需要返工的单例：`ferry-v4-double` 留出相位仅1/12通过（轻9/12、中6/12）；`thorn_wall-m2-v0` 中扰动虽然稳定出口9/12，目的动作却0/12，且存在普通跳/二段跳/纯墙跳的便宜替代。这些与其余已知捷径候选共5条标为诊断 `REWORK`，仅保留供比较，不准入批量成品池。旧平台输入的动作词省略了登船跳元数据，最终purpose显式检查真实“两次地面跳+离船动作”，未来生成器已修正该字段；未改历史输入。

执行账本保留 wall/child CPU/RSS：校准批次28.86s wall、30.39s child CPU，子进程峰值约1.50GiB；留出批次38.79s wall、43.69s child CPU，累计子进程峰值约1.85GiB。RSS来自同一Python进程的 `RUSAGE_CHILDREN.ru_maxrss`，是批量运行高水位，包含大量完整轨迹，不能当作单Module或游戏Runtime内存。当前批处理评价架构需要流式输出/分批回收后才能讨论部署成本。

## 区域特色已经影响真实几何

区域输入是结构化 JSON，不是任意一句自然语言。支持的机制、能力注册表、几何编译器有明确边界。区域名、颜色和说明文字不具备通关或区域符合效力。

`regions/sky_islands.research.json` 的约束包括：向上至少120wu、岩块宽高32–160wu、连续墙面最多180wu、岩块竖向分隔至少24wu、允许重复动作、不强制每段使用全部能力；研究配置禁止荆棘/平台/锯轮，入口和出口实际支撑台有独立尺寸上限。它不代表浮岛正式美术与区域 Bible。

编译器依据真实参考轨迹保留墙面接触带，替换长墙，移除经严格签名识别的非区域压力 Cells，并重建索引。不能把连续高墙切成接触的小矩形伪装浮岛。过长接触带、未知荆棘宿主、端口被删除、能力缺失等会拒绝。每次变换使旧物理回执失效，必须重新执行。

`region-sky-v1` 的实测为：

- 16个基础 Cell/动作提案 → 12个可布置候选 → 10个符合区域几何 → **8个真实连续动作合格模块**。
- 合格模块上升240–428wu，其中3条实际执行墙跳、二段跳、钩索和反冲混合链；其他包含重复墙跳/二段跳。
- 2个区域几何违规候选被拒绝；另2个虽然稳定到出口，却意外中途着地，已按连续挑战不合格剔除。没有将它们算入8个。
- 8个模块各8次轻/中扰动：轻扰动59/64通过目的检查，中扰动39/64；单看稳定出口分别61/64和44/64。必须区分到终点与完成设计动作。
- 全流程154次真实物理运行，20.90s，包含扰动评价，不是单模块Runtime耗时。20个纯Python正反测试覆盖区域合同与索引/支撑保护。

全套可用能力从本局实际解锁状态输入。本次浮岛运行使用全部六项已注册能力，但具体挑战只使用其中子集。没有强制每段用尽所有能力，也没有为满足区域要求暗中授予能力。

独立复核发现旧浮岛输入中有一处元数据继承问题：墙跳提案的 `capability_contract.ids` 仍写提案的4项能力，而实际 `capabilities` 与真实绑定快照为全部6项。物理执行正确，旧输入/结果完整保留，旧contract只可解释为提案来源。未来生成器和派生交付已将旧值存为 `proposal_capability_contract`，按未改变的实际能力重建当前contract。交付中2条记录只改这些元数据，几何/控制/实际能力/见证帧逐项未变，补丁账本单独留存，并重新验证Web包。

`regions/mushroom_caverns.proposed.json` 描述弹射蘑菇与孢子气流，但游戏审计未找到真实实现。默认执行会报 `runtime_region_rejected:proposed/unimplemented=bounce_mushroom,spore_current`。只能查看草案，不能用普通平台/钩点改名充当弹射蘑菇。下一步必须实现真实组件、资源恢复语义、接触/高速扫掠/时序校准，才可注册生成规则。

## 试玩、录像与后续集成

本轮交付17个预生成候选：12个动态挑战+5个浮岛挑战。可手动操作，或运行真实 Router 输入见证。界面显示能力、实际机关相位/时钟/HP、提交/扣血/返回与无伤资格；重建实验会显式重置，受伤段落回退保留相位。

17个候选共7404帧在场景与生成器之间逐帧对照通过；最终独立Web包在Chromium通过17个完整回放和真实D/空格/R操作，页面/引擎错误为0。28.2秒四段录像来自真实原生Godot，包含墙跳压力区、锯口、实际载人平台和浮岛混合动作；原生与headless段落结果一致。20区域合同测试、2新增能力快照回归、12既有动作组合回归测试通过，870份受保护原件SHA256零漂移。自动浏览器检查仍不等于人类试玩或设备验收。

离线目前负责动作/几何/时机搜索、真实模拟、替代策略和扰动评价。后续 Runtime 应输入本局能力+区域配置+种子，在已校准参数域内提出候选、快速验证并保留有界失败回退；尚未实现运行时求解预算与完整肉鸽地图消费者。少量生成规则替代大量完整预制模块有正例，但不能据本批成功率推断长期丰富度。

Map Notes 下一步应增加版本化 RegionSpec 引用、已实现机关选择、基础 Cell 参数、预览动作轨迹及失败原因、区域与能力合同检查、完整见证/源版本回执。区域机关必须与游戏消费者共享定义，导出几何后必须重新验证。当前仅提供技术方案，未修改编辑器。

优先工作是独立多种子覆盖、低成本替代解规划、学习者/熟练玩家两档容错与人工盲测，再接质量多样性档案和 Macro/Map 节奏。高难不应单靠缩小误差窗口；苦痛之路级设计还需要可读性、机制递进、恢复点与整段节奏的人工评价。
