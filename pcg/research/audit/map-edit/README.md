# 关卡手记 · Map Notes

一个零依赖的网页关卡草图编辑器，为 Gunman Rush 记录关卡想法。

在线入口：https://zhipijun1996.github.io/map-edit/

此前的 Sites 入口：https://gunman-map-notes.silkyball18.chatgpt.site

打开就能摆地形、机关、敌人，画物体轨道和人物动作路线。手机和电脑共用同一个界面。无需安装、无需账户；不运行游戏物理。

- 「模块库」提供 177 份可编辑参考：72 个原始 `.tres` 模块、51 份森林代码模块 / 变体、36 个工坊组合片段、18 条工坊连续路线。
- 点击模块会生成自己的草稿副本；原版始终留在库中。
- 模块库按平原、森林、通用、工坊分类，支持按「已接入正式流程 / 已接入开发试玩 / 未接入 / 待核实」筛选。接入判断绑定源码入口调用链；消费者变化会让旧结论失效，变为待核实，不把引用次数当接入证据。
- 「修改原模块」保留原模块身份；「新增变体」明确创建新模块。右侧可以切换本次用途，导出的工程带 `changeRequest`、原模块目标、基线提交和对象增删改列表。PNG 也会显示修改用途与原模块 ID。编辑器不会自动把草稿写回游戏。
- 左侧点击添加，画布拖动摆放；选中对象后调整尺寸、旋转、文字、轨道和机关目标。
- 人物路线逐点绘制，填写每步动作。下方路线菜单可切换主路、支路、奖励和返回路线。
- 直线 / 折线轨道逐点绘制；弧轨拖出曲线，再拖黄色控制点调整弧度。起点靠近物体中心会绑定，也可手动选择。
- 时间条预览机关运动和人物预期路线，不代表真实物理通关。
- 「导出图片」生成 PNG，包含说明文字；「保存工程」下载可再次编辑的 `.mapnote.json`，通常无需手工接触 JSON。
- 本机自动保存不跨设备、不上传服务器。换设备或备份请保存工程文件。

## 开发

```sh
python3 -m http.server 8080
# http://localhost:8080
npm run check
```

无需 npm install。仓库 Settings → Pages → Source 已设为 GitHub Actions；推送到 `main` 会自动执行 `Deploy editor` 工作流，也可在 Actions 中手动运行。工作流检查通过后发布到 `https://zhipijun1996.github.io/map-edit/`。部署仅上传静态页面与模块库，不上传工具和原项目源码副本。Sites 入口保留此前版本，后续以 GitHub Pages 为准。

## 模块库来源与覆盖

绑定 `gunman-rush@74d8a06b42cb2bc2c5023f1bfe1a4fbc4b163074`。

原始资源与森林工厂由 Godot 4.7.2 Standard 实际加载和执行，随后转换成编辑器对象。保留平台几何、单双向平台、各方向刺面、锯轮与摆渡运动参数、端口和原始路线；平原风铃及门的额外布置来自 `config/plains_shot_latches.json`。

库中包括历史模块和未正式准入的森林候选，类别明确分开。导入不授予新的正式准入状态。没有完整动作记录的模块显示原始安全锚点，不伪造通关轨迹。根据 action_program 绘制的反冲点仅作示意，保留原动作程序和标记。模块外由整图消费者配置的敌人 / Boss 不臆造；无限 Seed 的大地图实例和现场生成的接缝不逐一枚举。只列目录但未实现的场所不补画成已存在模块。

每份工程包含来源提交、路径、原数据与编辑平移量，完整清单见 `library/coverage.json`。工程的 JSON 结构独立于游戏存档 / Manifest，不会被直接当作已验证关卡运行。

## 网页更新模块库

模块库右上角的「更新模块库」会读取游戏 `main` 最新提交，以及编辑器仓库已生成的新库。目录和模块文件固定到同一编辑器提交，逐文件核对 SHA-256；加载失败不会替换当前库，也不会覆盖正在修改的草稿。

若游戏已有新提交而新库尚未生成，网页提供「在 GitHub 运行同步」：进入后点击 **Run workflow**，保留 `source_ref=main` 即可。网页不保存写令牌，因此 GitHub 需要这一次确认。回到网页可自动检查生成进度或点击「再次检查并加载」。

同步工作流会锁定一个游戏提交，完整下载新快照（不跳过已存在文件），用校验过的 Godot 4.7.2 提取原始数据、重新分类、验证，再提交模块库并发布 Pages。失败不提交半成品；出现尚未支持的新模块结构时保留已发布旧库，工作流给出错误。新增资源模块会自动枚举，代码工厂仍需对应提取适配器。接入证据与消费者指纹在 `library/integration-rules.json`，更新脚本不会自动重签旧证据。

复建流程（需要项目指定的 Godot 二进制）：

```sh
python3 tools/sync_library.py --ref main --godot /absolute/path/to/Godot_v4.7.2-stable_linux.x86_64
```

`library/source/` 保留固定版本的只读源码与配置快照，便于审计 / 复建；不带游戏大体积美术。若更新游戏版本，须重新下载同一提交的索引与依赖，再重新提取，不只替换提交号。

## 模块能力要求

右侧「能力要求」支持必需能力列表，以及多组「任选一种」条件。例如：`钩索 且（二段跳 或 蹬墙）且（射击反冲 或 自定义能力）`。展开后勾选即可，支持自定义能力、补充文字、撤销与本机保存；模块库搜索能力名称即可查找参考，工程和导出图片都包含条件。

`capabilityRequirements` 的 `allOf` 是全部必需；`anyOfGroups` 每组内 OR、组间 AND。`status` 分为 `unspecified` 未填写、`partial` 部分声明、`defined` 已确认完整。只有已确认完整且条件全空才表示无能力锁；旧草稿缺少字段时按未填写处理。`evaluateRequirements` 可供后续消费者筛选：不满足已知条件返回 false，完整条件满足返回 true，信息不全返回 null。

导入只读取源码显式声明：森林 `requires`、资源模块及出入口的跳跃 / 射击次数与爆发反冲要求。原参数保存在 `source.capabilityEvidence`；工坊合并组成模块的显式要求，其回放验证配置不当成最低能力锁。源码声明暂不视为完整通关需求，能力名称也不表示游戏已实现该能力。设计更改与源码原值分开，工程 `changeRequest.capabilityChanges` 记录前后差异；只有调整能力属性时也能识别为原模块修改。更新模块库会重新导入，不覆盖已有草稿。

这些是编辑器设计属性；游戏的随机生成器尚未读取此工程格式。接回游戏时需要把能力条件加入候选筛选，依旧验证资源、接缝与物理通关。

## 模块难度评分

右侧「模块难度」提供 1～10 的整数评分和评分依据，支持撤销、保存重开、工程导入导出；图片包含分数与依据，模块库可按分数或未评分筛选。未评分用 `null` 表示，旧草稿自动兼容；现有 177 份参考没有统一的 1～10 分数据，保持未评分，不把机关数量、原压力字段或工坊能力配置擅自换成分数。

评分口径：玩家已拥有所需能力，按预期通关方案的必经主路线评估，不计额外强化。综合精度、时机、动作连续性、失败容错和战斗压力，以最难必经段为主，持续压力可适当上调。支线不抬高主路线评分；不同能力组合差异大时在依据中说明或另建变体。设计分数应经过试玩校准。

| 分数 | 参考 |
| --- | --- |
| 1 | 休整：安全通行，几乎无失败风险 |
| 2 | 入门：单个基础操作，宽落点、高容错 |
| 3 | 简单：少量操作组合，有安全停顿 |
| 4 | 普通：观察机关、调整落点，短动作链 |
| 5 | 中等：多步配合，有明确精度或时机要求 |
| 6 | 偏难：连续操作、移动目标，失误代价较高 |
| 7 | 困难：长动作链、窄时机或多重压力 |
| 8 | 高难：持续精准操作，低容错 |
| 9 | 极难：高压操作长时间串联，补救极少 |
| 10 | 极限：接近已验证操作上限，几乎不容失误 |

工程 `difficulty` 保存 `version:1`、`scale:"gunman-rush/module-difficulty/v1"`、`score:1..10|null`、`note`，统一口径有独立版本号。修改原模块时保留 `baselineDifficulty`，`changeRequest.difficultyChanges` 记录前后值；只改评分也会成为明确的原模块修改。原库分数在 `source.difficulty`，更新库不会改写本机草稿，也不会把本机评分发布为原版评分。

后续生成器可先筛选能力与接口兼容，再按局部目标曲线挑选评分接近的模块，例如 `2→3→4→2→5→6→3→7`，穿插休整。整体难度设置调整目标曲线、峰值和高压段密度，保留模块固定基准分；整图额外敌人、连接段和连续消耗需要另行修正。未评分模块不应当作低分自动参加曲线匹配，整图难度也不能把模块分数直接相加。这次仅增加编辑器标准与元数据，尚未改动游戏生成器。

## 后续接入真实项目

使用「保存工程」把文件交给 Codex 即可。`objects` 包含稳定 ID、类型、尺寸、位置、轨道绑定、控制目标和文字；`route.points[].action` 保存预期操作；`description` / `constraints` 保存设计说明与必须保留的关系。

后续转换器可把实体与平台映射到 `PlatformingModuleDefinition.platforms`，刺面映射到 `PlatformThornDefinition`，锯轮 / 直线摆渡映射到现有 Definition；钩索、复杂场所和动作步骤映射到森林模块工厂。弧形轨道等尚无通用运行消费者的对象保留为设计需求，不能默默降级。正式尺寸、人物资源、接口接缝和动态相位仍在游戏中验证。

快捷键：V 选择；R 地块；空格移动画布；滚轮 / 双指缩放；Ctrl/Cmd Z 撤销；Shift Ctrl/Cmd Z 重做；Ctrl/Cmd D 复制；Delete 删除；Ctrl/Cmd S 保存工程。
