# Block128 disk reuse v6

The original `catalog_v2` and persistent `CandidateLibrary` were invoked in 21 independent Python processes against the published 21-version manifest. Three unchanged, full Challenge Specifications retrieved the expected N08 and N11 west/east immutable versions. No generator or physics was called. Together with the preserved earlier receipts this records 21 reused Block candidates.

Each of the three requests was independently changed in six ways: Block256, one-Block narrower space, a north-facing first port, an unverified falling entry state, automatic seam resource reset, and a major traversal-item reward. All 18 requests returned `unsatisfied` with search scope/conflicts. This is evidence that unsupported adaptation is rejected; it is not a proof that a new implementation could never satisfy it.

`receipt.json` binds every request, response, manifest, original record, prior receipt, and original query-source hash. Each response is also saved separately; the receipt contains the exact reproduction command. No original source, candidate record, or physical evidence was modified.
