以下后三项只是规则测试数据，没有应用到 Module/生成地图，也不授予通过资格。精确输出：[m24-rule-cases.json](../../../evidence/runtime-integration-930001/m24-rule-cases.json)。

## 尚缺什么，不能从几何冒推什么

- 1.1.0 缺 reward↔Route 声明：requiredRewards=[] 只说明**未声明**，不说明没有奖励、不可领取、可删除或 A↔B 必经过箱。不能按最近 Route 连线补关联。
- 缺去领奖并回来/出去的实际可达路线与动态证据：静态净空只是必要条件；有移动 carrier、铃控、相位、跳跃/射击资源。A↔B 被保留不代表奖励站位受到作者折线保护；更不能因 reward 被封就宣判 A↔B 都不可通行。
- 当前 `gear_seal` 只保护剩余作者路线段的身体膨胀路径；它不是领取站位/机制依赖检查。最小改进应消费现有 seals、reward_sites.region、真实支撑与玩家身体；对“全区被排除”报告确定冲突，对未证站位/路径保留 UNKNOWN，再用定向原生验证补证。
- 未解决奖励目标/可选内容策略时，报告具体 instance/reward/obstacle/坐标与原因。拒绝的是本组合，允许生成器选择其他符合现有规则的组合；不删除箱子、不扩大禁区、不一律禁用 `idea-orbit-choice-001`，也不修改当前冻结地图制造通过。
- 最小输出可以沿既有诊断携带 `M24/reward` 和 C seal 的上述几何事实，不要求新增 Module 契约。是否新增经过审阅的出生/封口兼容声明另议。
