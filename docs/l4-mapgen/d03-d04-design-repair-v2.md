# D03 / D04：玩家取舍与方案漏洞分开

这里的“矛盾”指两个目标相互牵制，不是方案应当保留的逻辑错误。原案见[五份创意](plains-five-designs-v1.md)。本次先修正设计约束；没有新增Godot实验或完成候选，不把逻辑说明当成可玩性证明。

## D03：这次借火，减少下次机会

原取舍是：空中命中敌人获得续枪，能走更直接的空中路线；但真实伤害也消耗敌人HP，后续能借的机会变少。两条可选近路共享同一敌人，机会用在哪边才成为判断。原3HP及有限伤害/回充已有4份机制探针；未验证两个实际路线的空间竞争，不能据此宣称完整D03已成立。

若两条路随便普通跳就同样好走，敌人只是可有可无的弹药装饰；若敌人死后出不去，则是方案漏洞。修订为：

1. 主出口永不依赖敌人存活；两个奖励目的地也都保留敌人死亡后的实体路线。玩家资源按真实落地恢复，敌人HP不重置。
2. 活敌提供的是一条短空中连续近路；敌人耗尽后改用分段落地、恢复、再起跳的路线。替代段应是短而有动作内容的支撑组织，不用长走廊惩罚玩家。
3. 命中机会在两条近路之间共享，收益/动作成本事先可看懂。所需命中数必须由实际地貌与原动作求解，不在验收器里强制“必须打两枪”来制造稀缺。数值例子不是通关结论。
4. 保留地面清敌的合法选择：换取较低战斗压力，同时放弃后续借火路线的优势。敌人是否实际形成威胁也须验证，不把名义上的Enemy当成已经发生的两难。
5. 显示与真实HP绑定的余量。依次验证未用、受伤、死亡、失败后重试、先取一处后取另一处、两处均未取而敌人已死等连续状态。

核心体验不变量：玩家能指出“我把有限命中机会花在这里，所以后面改用另一段动作路线”。若仅有HP计数变化，或同一策略在所有状态始终更优，退回设计，不计新关系。

## D04：方便取宝的停位，不同时兼顾最快回程

原取舍是：平台停在中间能接通回程缺口；停在奖励侧能接近侧洞，但中间回程缺少这块支撑。去程同一枪既反冲跨越，又暂停平台，给回来时留下状态。

|持续停位|实际得到什么|需要承担什么|
|---|---|---|
|中位|可直接使用平台完成回程|奖励侧不能顺手到达，需要额外动作或重新调台|
|奖励侧|可落到侧洞入口取得奖励|不能按原中位路线直接回来，要走另一段动作或调整平台|

若两停位都能轻松取宝并返回，只有名称差异；若回来站在安全地面补射一下就能任意改位，提前布置没有实际价值；若停错就软锁，则是恢复设计失败。修订为：

1. 用真实开口距离、高差、岩体与身体净空使两个停位承担不同通路；先求两位各自的真实路线，不能仅在图上画不同箭头。
2. 出发时能看到奖励侧与回程缺口。原启动/暂停能力保持不变，不增加自动停靠、隐形射击限制或自动回位。
3. 从右岸/奖励侧不能无成本改位：真实岩体遮挡控制铃的射线；要调整，先经过一个短的跳跃/反冲段到可读的调台位置。不能只增加等待时间或往返空走来制造代价。
4. 不靠一次停位强迫永久二选一。取宝后仍可通过替代动作返回或到调台位置纠正；任何停位/错过落点都有待验证的恢复路线。
5. 比较中位与奖励侧两种完整去回程、取宝及修正停位的连续程序，保留角色/平台/奖励状态。若一种方案在相同目标下始终更短、更安全且动作更少，原取舍没有成立。

核心体验不变量：回来时确实用到或修正去程留下的平台位置；该状态改变回程的动作组织，而非只改变等待秒数。

## 后续原型顺序

先逐案只做一份核心原型，核对上述取舍是否在正常速度游玩中可见；成立后才做多端口/尺寸适配和完整质量批次。D03仍缺完整共享状态路线与HP表现，D04仍缺停位对应路线、射线遮挡和恢复的真实求解。不得因“已有Cell”就标成已实现。

用户的新D05改案另存为`human-d05-bell-carrier-catch`：同枪反冲离台并启动平台追赶接人，再二次起跳。它不是木箱Cell，也不自动等于旧追台样品，尚未运行原型。当前先按本次要求修清D03/D04的设计逻辑。
