## 本轮实际交付

`generation/maps/valley-complete-v1/report.html` 提供三段连续真实 Godot 录像、整图、主游戏正式整图与拓扑对照。新图为8个Module/9处直接接缝/2个规划回环，加一条远端宝库支路；覆盖完整小区域入口、出口、分支、汇合、宝箱、交易和回程。**没有接入 Boss 战、两图战役和存档；不是正式区域流程的完整替代。**

1. **最新正式 Tile**：采用主游戏 main 使用的 Underworld native32px 地形、同源精确边界适配和视差背景。不是把矩形画成假斜坡；真实碰撞仍由 Module 的矩形并集构成。地形构造器、shader、构建JSON、背景源逐SHA绑定；新动态背景原件补入隔离实验资源，不改870保护原件。角色/战斗物理仍是12f6cb0绑定；主游戏当前玩家配置逐字节相同，不据此宣称所有最新战斗代码也已迁入。
2. **空中射击停靠台**：原 ShotLatch 的 bind_motion 控制原 ModuleMovingPlatform。先击谷底风铃释放平台，上升后起跳，在空中射击另一枚风铃，把平台停在上层码头，同时靠实际反冲转移到岸边。最终案例第919帧提交停靠，平台位置[1400,566]、motion_clock=8.4833，射击时角色在空中。没有设置角色位置或补资源。
3. **敌人回充接力 Cell**：东岸增加“巡风者宝库”Module；沿用已有经过测量的 enemy_refund 动作核，重做 Map 需求、位置、标准输出和下层回程。真实敌人命中返还空中射击次数，第二枪反冲到远端宝箱；回程另用原武器击杀仍存活的守卫，不能由单程成功推断回程。
4. **三个宝箱与一个商人**：悬桥封闭小龛12金币、谷底封闭小龛8金币、远端宝库16金币。原 SimpleRoomReward/RunWallet 记账；商人使用原 ShopService/BuildState，8金币购买原 damage_blue 道具。宝箱服务须有对应风铃/空中敌人命中证据且实际到达支持面。手动版本靠近领取宝箱，E购买；自动录像的交易由显式测试输入驱动，未赠送金币。

## 门为何可以绕过，以及这次如何处理

旧生成器在开放接收面边缘摆一个门，再用目标动作回放证明经过门，无法排除更高的反冲轨迹、下穿或远端绕回。门也没有保护独占收益。本轮不把所有路径强制排成同一门序列：

- 西岸上层门接在真实岩岸与局部悬岩之间；迎风脊门上方有真实岩盖、下方接接收岩岸。门保持正常100/180世界单位高度，未用高耸栅栏堵住整个天空。
- 悬桥门保护上层宝箱小龛；下方齿轮桥是明确允许的替代路径，跳过门就拿不到该宝箱。谷底门同样保护实际宝箱，并解锁上层回程平台。这两处小龛使用真实顶/底/后侧岩体，只有门是入口，绝非Module默认四面外墙。
- 下层探索路线仍可绕开上层挑战；这是职责明确的路线选择，不再把这条路线计为“必须开上层门”。地图并未承诺每个主线走法都必须射击，必经性和奖励路线分开声明。
- 已解锁门保持开启，返程侧增加原 add_access_bell 接收器。收紧门后原来被掩盖的返程阻塞已修复。

**独立检查**：`gate_audit.py` 用实际实体岩体和门，按24×36角色身体扩张，构建精确矩形排列并搜索自由空间。两个宝箱在门关闭时均与外界隔离，门打开后有几何通路。单向平台不作为阻挡证明，避免把能下穿的平台当封闭顶/底。实际通关另有 Godot 见证。

**有界反例**：4处目标 × 3种跳跃保持 × 3种射击时机 × 6种射击角度 = 216次真实局部策略，未出现对应门始终关闭却到达受保护目标。它覆盖明确的有限策略，不是万能平台运动求解器；局部测试有显式起点，不能冒充从地图入口开始的整图测试。

## 真实验证、失败与改进

最终 `valley-complete-release-v1` 五条连续路线全部通过：主线720帧/12秒；宝箱→升降→空中停靠→商店→回程1662帧/27.7秒；远端宝库大回环1998帧/33.3秒；下行捷径1278帧/21.3秒；下层奖励回环1628帧/27.13秒。途中不重建、不传送、不补资源。实际完成的端口腿覆盖9处接缝的18个方向。

`valley-complete-release-holdout-v1`：冻结最终几何后，新齿轮相位 .07/.29/.59/.83 × 五路线，20/20通过，同时改变敌人初始待机时间。受铃控制的升降台固定设计起始码头，不能把随机码头位置当同一内容；未测试人类瞄准误差或帧时机扰动。

三段原生录像分别720、1662、1998帧，共4380帧，坐标/速度/输入/资源/碰撞支撑/敌人和机关逐字段一致，最终钱包、商品、停靠回执也一致。正常1倍60Hz，保留等待、预热与末尾约1秒完成画面。只对原 projectile damage source 的进程局部 ObjectID 后缀沿用已有归一化；伤害对象、HP、帧和输入不放宽。

最终静态审计：110个独立静态对象，111个源对象中去重一个声明共享落点；Map新增地形0、遗漏0、孤立对象0、未声明跨Module实体重叠0。几何SHA c35ce9c29c9de2583c84154160716024e12bb6ee27ecb11bc5942aa24cdcf032。

完整失败留存：标准敌人导出坐标重读错误；宝箱实体地板使旧下穿失效；回程台阶被上方岩岸挡住；返程守卫接触伤害；新门拦住原回程；原 join_waypoints 误删同终点的原地射击动作；停靠射线先撞到邻近另一枚风铃；Web精简资源包缺JSON动态加载的边界/门材质。失败没有覆盖或重标成功。两个新回归检查保证同终点解锁动作保留、重复纯走路端点才去重。

## 与主游戏当前正式地图比较

以正式 DemoApp 当前准入的 **v12 root-bell-spaces** 为准，非生成器未配置时的旧v10。正式5个共同基线Seed `valley-comparison-0..4` 实际生成，manifest/hash随 comparison.json 保存。额外使用原 live formal Harness 跑 Seed0 fast/kill_from_bank_v2，3506帧/58.43秒到达Boss准备区，15枪，HP5→4，无中途重置/传送/资源注入；Boss战未跑。原 legacy fixture 的41项通过只作为历史路径对照，不冒充正式v12验证。

| 维度 | 主游戏正式 v12，5 Seeds | 新风谷，本轮固定样品 |
|---|---|---|
| 空间规模 | 20个探索地点、59–63个Module实例 | 8个完整地形Module |
| 探索连接 | 26–27条、7–8个独立环 | 9条、2个独立环+远端奖励支路 |
| 地图变化 | woven_layers/crossroads/linked_rings，5个独立hash | 1个冻结空间语法；尚无多Seed体验证据 |

| 奖励与经济 | 4个宝箱、正式物品/资源选择、商人、跨图状态 | 3个宝箱、8金币商店、真实原服务；隔离单图状态 |

主游戏在规模、种子变化、生态、Boss和流程完成度上明显更完整。新样品更容易审阅“这一枪为何有价值”、收益是否在挑战内部、返程是否真实跑过，以及Module对象是否直接构成整图。**不能凭环数、截图或本次无伤策略宣布新生成器整体更好**；也不能将58秒与12秒当公平速度对比，地图规模和终点定义不同。

## 架构、自增长与后续接口

仍由既有 Mission/Exploration 契约驱动 Challenge Specification；本轮新增 mechanic_requirements/gate_design，明确“上层入口”“独占宝箱”“允许下层替代路线”。没有重写PR #1图算法。`valley_complete/director.py`只是现有空间语法的有界内容修订，**并非通用高质量多Seed导演**。

生产器调用现有 open_landforms 和已有动作核，缺少的巡风者宝库按需求生成。宝箱、商人、敌人、返程接收器和平台控制关系均写入标准 Map Notes+generationContract，而非只在截图层添加。canonical重读核验原始对象；共享拼装器只平移原件和显式共享落点。

最终8份Module及完整Map技术回执进入原CandidateLibrary的版本化隔离候选记录。`valley-complete-reuse-v1`独立进程复用8/8份，生成调用0，再实际跑通主线720帧。人类认可、生产准入均仍关闭；通用关系UNKNOWN不因这张图通过而提升。跨Map部分匹配和更一般的需求求解仍未实现，本轮不能将精确缓存复用说成通用自增长已完成。

## 复现

恢复原 `godot-runtime-v1`、`open-valley-sample-v1`及本轮 `valley-complete-v1`，使用原4.7.2官方引擎并执行一次导入。归档包含全部本轮失败/源快照/原始gz轨迹、正式v12捕获和新增背景原件；不包含可重建AVI或引擎二进制。

```sh
python pcg/tools/restore_archive.py valley-complete-v1 --extract
python -m pcg.map_directed.valley_complete.run --name fresh-valley --mode full
python -m pcg.map_directed.valley_complete.gate_audit pcg/results/fresh-valley
python -m pcg.map_directed.valley_complete.run --name fresh-valley-states --mode holdout
```

原生软件渲染和写电影成本不代表正式Runtime FPS。下一轮应在相同规模/角色/内容预算下，将本轮动作关系加入多Seed导演，再比较路线选择、奖励深度、已知地标回访及人类观感；正式Boss/地图状态接入需另一组完整live-game回归。
