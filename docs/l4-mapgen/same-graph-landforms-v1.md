# 同一探索图驱动物理拼装：高崖与溪谷验收样图

本轮目标是落实一张图，而不是扩大数量：两条空间与动作关系不同的主路线、一次真实汇合、一条独特挑战及实际回程的奖励支路。已做出7 Macro / 7零间隙接缝的真实Godot小地图；旧岩井模板0，Map补平台0，删除蓝图边0。仍是一张有限规则构造的验收图，不是完整随机大区域或人工趣味批准。

用户同时询问旧Module是否需适配。结论是：接口可以小幅适配，内部挑战继续保持像素精度；不能把所有几何放大取整，更不能通过拉长出口岸体把平路伪装成爬升/枢纽。本轮复用原限时击铃和尖刺窄槽内容；后者增加同一几何中的独立逆向反冲策略。新增分叉崖、爬升肩岩、下坠制动崖、折返攀升和汇合地标配方。这些都是新版本，源证明不继承，独立方向与整图重新验证。

## 蓝图与实际世界的对应

唯一输入职责图由 `pcg/map_directed/graph_landforms/graph.py` 产生。图没有理想位置、旧房间坐标、旧岩井布局或L/R行号。每个节点的Macro职责和每条边的局部端口职责驱动实际候选匹配，同一个图对象经验证、输出、CSP、标准文档往返及拼装后再次核对。`blueprint-world-correspondence.json`保存逐节点内容版本/位置、逐边真实重合Port；不使用另一个更简单的图替代。

| 蓝图节点 | 实际Macro职责 | 物理关系 |
|---|---|---|
| start | 非对称分叉崖 | 同一个进入状态，可向高处或下层出发 |
| rise | 上升肩岩 | 候选宽640/768、高差128/256；联合选择后本图上升256 |
| ridge | 原内容适配的限时击铃窗 | 高路空中击铃和反冲；不发额外宝箱 |
| cliff | 下坠制动崖及深处支路入口 | 低路下降256；空中射击刹停转入岩唇下，另有向深处的去向 |
| switchback | 折返反冲攀升 | 低路重新上升512，利用原跳跃/落地回充/射击资源 |
| landmark | 不同于入口形状的开阔汇合地标 | 高低两路到达同一个实际位置，能沿下路返回 |
| cache | 尖刺窄槽折返宝箱 | 进入取得1箱18币，反向通过同一挑战，再返回cliff |

主线分别是`start→rise→ridge→landmark`和`start→cliff→switchback→landmark`。奖励为`cliff→cache→cliff`，其后继续低路到地标。跨路线巡回真实执行`start→rise→ridge→landmark→switchback→cliff→start`再走低路完成，全程只有一个角色、一个世界时钟，无传送或中途资源重置。

图中箭头表示本轮声明并验证的方向。没有证明未声明的反向绝对不通，不能把它当已实现的强制单向锁。实际平台世界还可能有未搜索的技巧捷径；两种具体反例不是对所有玩家输入的穷举。

## 共同内核如何改变

- 原 `shape_search.search(...require_blocks=True)` 仍做实际碰撞、动作净空、Block所有权、端口profile、环闭合及运动条件的有限CSP。本轮没有另建空间求解器。
- `graph_landforms/build.py`按节点职责匹配候选，端口高差、宽度、地貌轮廓和动作路径来自候选变量。没有读取旧Map的Port方向或位置。每个候选的所有物理开口都对应蓝图边，不保留旧岩井的unused开口。
- 在共同12000展开上限内做12次候选搜索，筛选完整解，而不是找到第一张能拼的就交付。拒绝连续水平带、缺少必要高差、重复枢纽家族和过低预留空间利用率；对合格解选较紧凑的一份。静态筛查只是设计代理，不能当美术/趣味评分。
- 选中的高路内部Port高差为`-256、0`，低路为`+256、-512`；最长连续同高穿越分别1、0。预留Block占全图包围格38.6%。中央空腔保留作高低路线的分隔，但它的可读性与地貌表现仍需人工观感确认。
- 使用原 `direct_join` 标准Module导出、版本核验、重新读回和逐对象拼装；世界中的平台全部归属具体Module版本。原 `BlockEngine/FeedEngine` 扩展只增加新源冻结，角色、机关、Router和物理规则未变。
- 标准文档关系仍UNKNOWN，具体方向见证存实例侧车。通过后进入原CandidateLibrary的隔离实例/逐Module payload索引，不自动批准生产复用或人工质量。

12次校准搜索有9份完整解通过静态筛查，3份因高路缺少足够爬升被拒绝。独立留出运行重新执行同样预算与选择规则；总CSP求解约0.045秒，不含源验证、导出和Godot测试。没有据此宣称任意图或完整区域都能实时生成。

## 真实证据

独立Macro最终校准28/28方向策略通过。整图校准5/5另记；冻结后新留出11/11：5条常规整图路线与6份新输入扰动，固定流`same-graph-input-51391`，±1帧/±1°，没有用失败挑幸运Seed。实际覆盖全部11个声明有向连接，逐边检查身体穿过Port开口、状态传递、全程预留Block与同一actor epoch。

| 常规整图策略 | 物理时间 | 射击 | 实际金币 |
|---|---:|---:|---:|
| 高路 | 11.20秒 | 6 | 0 |
| 低路 | 14.35秒 | 10 | 0 |
| 奖励折返后完成 | 29.53秒 | 20 | 18 |
| 跨路线完整回环 | 39.37秒 | 22 | 0 |
| 全部声明方向巡回 | 77.87秒 | 46 | 18 |

`graph-landforms-checks-v1/same-world-choice.json`核对前三条路线的全部平台/机关/危险/奖励/出生位置哈希完全相同，初始实际位置、速度、落地、射击资源、生命和模块时钟也相同。这是同一处的可选择路线，不是分别重建不同地形完成两个出口。

三段原生正常速度影片为12.283/15.433/30.617秒，实际1280×720、60Hz，分别672/861/1772物理帧，共3305帧逐字段严格一致；包含启动、实际等待和末尾1秒冻结。首次常规录像不代替新输入扰动，程序操作不代替真人手感。

两个同地形、同物理、同外在目标的简化输入失败：把瞄准铃铛改为不瞄准的斜下反冲，角色被门阻挡；省略进入奖励窄槽的反冲则触及危险。前者仍保留射击反作用力，并非用“没有按指定动作”判错。仅是两种有限策略证据，不能签全局不可绕过。

## 保留的失败

- Macro v1有27项被配置校验拒绝（walk预算超过既有360帧上限，以及旧Definition要求不同进出场景标记），不能把它们计为真实动作失败。单Port折返保留一个公开Port，场景完成标记与Port声明分开，没有凭空增加第二个开口。
- Macro v2实际20/28通过。主要问题是落点在上层岩体下方，身体顶部被挡4px；停在上层平台边缘却要求下层落地；以及过宽水平逆跳。没有扩大角色能力或重写位置。移动真实落点、使用原单向台下穿输入、缩短跳跃前的站位后，v3才28/28。
- 后处理首次调用旧统计工具时，旧工具不认识新`search+design`记录层次。失败原件保留；统计器兼容新旧结构，原始物理结果未改。

## 仍未达到的目标

这次证明的是“同一图驱动物理拼装”及小样的高低路线/汇合/奖励回程。职责图目前是明确编写的验收拓扑，Macro是少量可执行配方；不是任意自然语言自动创意生产、广泛多Seed拓扑或40～65节点完整区域。

局部岩体仍有直边，部分回程仍是阶梯式落脚；图上的中央空腔是否显得空、奖励回程是否过长、两路是否都值得主动选择，应据这次视频观感决定。没有因为物理通过就签“更漂亮/更好玩”。没有Boss、主要构筑道具、商店、全区域经济平衡或真人分钟标定。

地图、Module和动作一起设计的价值已经可检验：若库只剩同高左右穿越、相同枢纽，构建会拒绝职责缺口，不能再换用旧行列骨架冒充蓝图实现。下一步应针对这张小样的观感改轮廓与内容，再增加有区别的完整Macro，不先重复扩大数量。
