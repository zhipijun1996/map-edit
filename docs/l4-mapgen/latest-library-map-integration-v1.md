## 从失败得到的实现变化

1. 原目标不等于安全离场。活敌仍可在目标之后挡住新的外部端口；源spawn在后墙/闭门内侧也不代表能从外面进入。当前明确拒绝已识别的后墙/活敌冲突，其余真实失败写入原工坊反馈 `pcg/feedback/workshop/map-library-integration-v1.json`。
2. 空间约束读取实际实体、门、危险和动作样本；补入移动台完整start/finish扫掠。显式共享且完全相同的落地实体在拼装时二合一，不作为另一个外来障碍误拒绝。其余邻接实体不享受豁免。
3. 回溯增加剩余链端口位移区间检查、闭合优先顺序和严格50k上限。按相对位置缓存完全相同的模块对检查，并做保守包围盒预排除，狭义碰撞/动作约束不变。保留各阶段与基础设施失败，未把多个校准阶段说成一次三次预算。
4. 仍采用源拥有的地形裁切/岸根深度适配，产生新几何版本。原轨迹只参与筛查，不能继承成功；每张拼装后的世界另验。没有Map新建地形。

## 画面与Runtime结论

新增内容已经带来落地补枪接力、顺序击铃、运动射线窗、活敌供电、引敌开门、换乘避险岛等差异。**长矩形岸体、横向重复和大块留白仍明显。** 原型库的外轮廓及固定骨架比材质更影响这个问题；本轮不能声称达到正式游戏协调感，也没有人工趣味批准。商店、Boss、高速空中接缝、通用回程、整图绕门反例不在已证明范围内。

报告的搜索秒数只覆盖CSP核心，不包含94份文档的Node校验、几何适配、进程启动和物理测试。当前Python研究原型不适合直接称为Godot Runtime性能结果；缺少正式Runtime移植、完整生成耗时/内存剖析与全局动态相位求解。约束和缓存可复用，不能据单次快速搜索宣称Runtime已达标。

下一步优先修复带外部进入/安全离开条件的完整Module关系及落点余量，让Director读取实际失败后有限替换；独立设计真正有共同选择点的分流/汇合Macro；再加入连续岩体/空腔/地标骨架。固定内容后做同内容旧/新布局及新的独立扰动对照。继续加版本不能代替这几项。
