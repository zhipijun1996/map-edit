# Map 驱动的 Module 内容生态：第一版闭环

本轮完成了**有边界的离线工程闭环**：小规模平原的 Map 需求 → 机制关系提案 → 逐 Module 搜索 → 缺失适配生成 → 标准合同输出 → 直接拼装 → 真实 Godot 整图验证 → 候选索引 → 下一次复用。固定三个运行的生成调用为 **8 / 0 / 1**，105 条整图策略通过，其中 84 条为独立相位样本。

这不等于已经实现“任意新创意自动落地”或“多 Seed 大地图品质稳定”。三个运行共用一个八 Macro、双回环的物理拓扑，第三次只变更一个限时门的需求。尚无真人趣味认可、Boss 战或大区域准入。先前 39 Macro 薄平台压力样品仍不通过设计验收。

## 基线和复用关系

- 分支继续 `research/l4-map-generator` / PR #1，未修改正式主游戏。
- 再次 fetch 检查 map-edit main `b9318cf82cdd182645b4b42137e5e8eaaeb75731`，已经是当前研究分支祖先；主游戏 main `26e7f2a4459623f35613a857da8a75e89daa3e62`。
- 物理仍使用固定的 12f6cb0 / 870 原件与真实运动、资源和机关，Godot 4.7.2 二进制 SHA 见每轮 `physics/source_binding.json`。正式美术使用已固定的主游戏表现绑定；没有给旧物理重新贴 main 标签。
- `ecosystem.run.design` 调用现有 `valley_complete.director.requests`，未另建同功能 Mission/Exploration 算法。
- 生成复用 `plains.rock_recoil.adapt` 和已有测量地貌；拼装使用 `direct_join.assemble/audit/canonical`；物理使用 `CompleteEngine`；入库扩展已有 `CandidateLibrary`。
- Module 输出继续 `gunman-rush-level-sketch/v1 + generationContract`。通用关系仍为 UNKNOWN，自动生产拼装关闭。隔离实验只能在重新验证整图的条件下使用这些候选。

## 创意层：因果关系，不是大量换皮

`ecosystem/ideas.py` 保留 16 个关系家族，按主路、奖励和回程职责产生提案。角色变化、Seed、尺寸或参数变化不增加关系家族数量。目前 9 个关系有本样品支持的适配规则，7 个仍为提案；这不是 16 个已验证有趣的模块，也不是在线模型生成。

每份 `design_contract` 包含：

- 玩家观察什么、作什么决定。
- 一次行动改变哪些状态，哪些效果具有因果联系。
- 岩体、机关、资源、奖励和路线职责。
- 可以推翻设计假设的反例，例如普通跳跃绕过反冲或在危险扫掠中等待。
- 失败恢复策略和能力资源政策。
- 原型实现状态与未评审的人工趣味状态。

原型实现能力由代码注册表决定，不能由输入中的 `implemented: true` 自行声明。提出“尖刺窄通道”，不会被悄悄替换成可生成的普通反冲平台。新关系仍需要开发对应生产规则，然后接受真实物理和观感审阅；当前并无自主编写任意机制代码的服务。

## Map → Module 的需求与搜索

沿用 Challenge Specification 的区域、节点职责、能力、端口位置和方向、空间限制、风险收益和预算，增加 `design_contract`。需求摘要忽略纯请求 ID、Seed 和展示标签，但保留实际能力、端口、形状、资源和玩法条件。

本版检索有意保留本地端口 ID 与几何条件，支持相同硬需求下的独立 Module 复用；不声称支持任意重命名、旋转、镜像、缩放或不同形状适配。更通用的范围匹配与约束适配仍需后续扩展。

每个节点按以下顺序运行：

1. 查询现有 `CandidateLibrary.payloads` 索引；检查源、引擎、物理基线、版本、合同和证据哈希。
2. 命中时复用原文档与版本；不能因为另一次导出就制造新版本。随后仍需整图验证。
3. 缺失时调用已注册生产规则，从已有测量地貌进行有需求约束的改造。
4. 不满足时返回具体条件：未知机制、端口/空间超出范围、缺少反冲能力、奖励值不匹配或门时间不在冻结搜索域。
5. 只有需求明确允许协商时，Map Director 才能执行一次局部修订。本轮测试将不可生成的门时间改为双方允许的 1.2 秒；拓扑、能力和端口未变。没有无限回退，也不暗中改成另一种玩法。

源或生产器发生变化会使候选变旧，重新验证后才能使用。当前为单写入者离线工具，没有并发写库、后台常驻生成或游戏 Runtime 创作服务。

## 真实内容及验证

八个不同尺寸 Macro 拥有自己的全部碰撞体。Map 只做直接摆放、已声明共享落点去重，没有补短平台或连接走廊。

- 114 个实心矩形构成岩体，9 个单向支撑构成有用途的平台。
- 移动平台 0，避免把乘升降机等待当本轮主要内容。
- 垂直与斜向反冲、低岩顶横向反冲、三段交替方向攀岩、独立快速下落回程。
- 2 个真实齿轮，1 个真实敌人；奖励长路线实际观测到 3 次空中命中回充，未把落地恢复算成命中回充。
- 3 个实体宝箱、1 个使用原 ShopService 的商人；金币由实际接触宝箱获得，没有起始资金注入。
- 两处宝库有真实岩体封闭，闭门分离检查通过。西侧与山脊上容易绕过、意义不明的旅行门已移除，保留其反冲地形。
- 岩拱宝库门时间由需求指定为 1.2 或 1.4 秒。内部增加原 ShotLatch 支持的回程侧射击接收器；专门测试进入深处、等待实际关门、真实射击重新开门、返回网络，避免只演示快速通过而忽略困住风险。

每张地图有七条连续策略：上层主路线、取宝攀岩购物回程、上层宝库与敌人回充长环、快速下降、下层反冲替代路线、东侧下层回程、延时门关闭后的内部重开回程。每条还使用四个独立相位样本，整段不重建、不传送、不注入资源。

既有入库逻辑核查实际压缩原始轨迹，覆盖全部 18 个有向图连接。单 Module 旧成功从未被当成新接缝、新状态或整图成功。

## 固定批次结果

`pcg/map_directed/ecosystem/protocol.json` v2 在实验前固定 Seed、门需求、候选上限、选择规则、留出 Seed 和验收条件。

| 运行 | 需求变化 | 生成调用 | 复用 Module | 整图策略 | 完整离线耗时 |
| --- | --- | ---: | ---: | ---: | ---: |
| ecology-0 | 冷库，门 1.2 秒 | 8 | 0 | 35/35 | 130.4 秒 |
| ecology-1 | 同硬需求、另一批相位 | 0 | 8 | 35/35 | 126.6 秒 |
| ecology-2 | 仅门改为 1.4 秒 | 1 | 7 | 35/35 | 165.3 秒 |

合计 9 个版本化候选，生产模块 0。时间包含进程启动、证据冻结、实际测试和 IO，不是 Runtime 地图生成时间；后两次受同时进行的软件渲染负载影响，不作为严格算法性能对照。

额外 8 项真实库与需求边界检查通过：不支持的创意停止、不可协商需求停止、一次显式协商、错误端口拒绝、缺少能力拒绝、生产调用拒绝 UNKNOWN、证据字节篡改拒绝、纯标签变更可命中。

## 失败与选择纪律

所有旧失败保留。岩体改造早期发现跨 Module 实心重叠、切分地面后的支撑索引错误、反冲高度不足、落在非预期岩体、普通跳跃不足以到达上层、岩拱顶棚与齿轮回程冲突。每次修订后重新跑真实整段，未删掉危险物来制造通过。

生态校准三轮中：第一轮验证限时门基础路线；第二轮专门的延迟返回失败，发现原 ShotLatch 的防夹保护使靠门站立时门不关闭，且测试射击将人物推离目标；第三轮改为深入房间再等待与向上射击，通过真实关闭/重开检查。独立留出前完成修订。

stability-v1 因合同审阅发现“输入自称实现某机制”和奖励需求不一致的漏洞而中止，没有挑选失败相位来调整地形。修复后协议 v2 使用新的预先固定留出 Seed；105 条均无候选替换、重跑挑选或事后降低阈值。

## 交付与复现

```bash
# 冷库 → 热库 → 单节点补缺；新目录拒绝覆盖
python3 -m pcg.map_directed.ecosystem.run --name my-ecosystem-batch --batch

# 真实库边界及证据完整性，不冒充物理测试
python3 -m pcg.map_directed.ecosystem.checks \
  --batch pcg/results/my-ecosystem-batch \
  --out pcg/results/my-ecosystem-integrity

# 生成可阅读报告
python3 -m pcg.tools.ecosystem_report \
  --batch pcg/results/my-ecosystem-batch \
  --out generation/maps/my-ecosystem-review
```

历史复现先恢复 `content-ecosystem-v1` 与原有 `valley-complete-v1` 及 Godot/runtime 归档。新归档按内容哈希去重保存全部逻辑原件，仍逐文件校验并恢复原路径，避免重复冻结资源膨胀。不会覆盖已更改的原件。

`generation/maps/ecosystem-v1` 提供实际整图 PNG、Mission/Exploration 职责图、结构化结果、正常速度录像及逐帧比对。视频由真实 Router 输入驱动，包含实际等待、购物和回程；不是人物轨迹动画。WebGL 手动消费者另跑移动、跳跃、射击、重试和整图视图 smoke。

## 接下来仍要解决的产出目标

1. 先实现提案中的新原型生产规则，重点是上下尖刺通道和主动射铃驱动平台；不能把本轮 9 个候选版本说成庞大的趣味库。
2. 将“同硬需求复用”扩展为语义检索、范围约束与真实尺寸/端口适配，每次修改保留独立验证。
3. 把已验证内容供应与 PR #1 的多个区域拓扑、约束嵌入双向协商，跑真正不同物理拓扑，之后再扩到超过主游戏正式单图规模。
4. 用实际视频反馈指导关系保留、改造和淘汰；用观察到的行为和空间决策维护质量多样性，不能靠 ID 或动作数量增加家族计数。
5. 补实际 Boss、区域生态、战役持久化和正式 Runtime 接入。当前 UNKNOWN 合同与未审趣味候选不得自动升级生产库。

本轮稳定的是已声明支持范围内的内容生命周期和有限策略可玩性。跨拓扑、多区域的稳定高质量产出仍未完成。
