## 方案判断和必要调整

Block把连续摆放转成有限离散选择，标准Port进一步减少位置/朝向组合；直接拼接消除了Map补路造成的长平台和挑战绕行风险。它并不消除循环图嵌入的组合难度，也不保证随机结果好玩。128是布局单位，32仍是美术Tile单位，两者约束不同。

Module可以占据不规则连通Block，但所有碰撞、交互体、机关扫掠和已知动作净空都必须预留。第一版采用排他的保守Block所有权；不能只看岩体不重叠，忽略反冲经过的空气。可以不带外墙，但未连接开口不能被悄悄删除或凭空封墙。现在保留为 unused Port，未来需要匹配封闭变体或验证其地图含义。

Port边界中心是几何锚点，角色的地面位置、空中运动状态和内部检查点是另外的信息。本轮水平接口明确14px身体中心偏移；上下接口独立处理跳跃反冲和下落。只能验证需要的方向，不能假定所有入口互通、把镜像或旋转视为免费复用。

Graph应先确定探索职责，但不应把每条边的位置和方向一次冻结，然后要求库被动适配。现有CSP联合选择形状、端口和摆放，有限回溯；无法满足时保留关键任务和边，报告需求缺口。最终的地貌主题、动作关系与图结构仍需双向反馈，不能靠网格本身产生设计感。

40～65实例/8～15主线实例是初始预算，不是先填满的配额。现有技术样图的主线程序用时仅14.2秒，替代路线21.7秒；与人类7～10分钟区域目标相距很大。8～15个节点承担420～600秒意味着平均每节点约28～75秒，包括挑战、探索和互动；当前几秒的L2挑战不能直接算成完整L3体验段落。不能通过增加等待、长岸体或重复拆节点“达标”。

## 实际调用路径

1. `experiments/l4-mapgen/region_network.py`：延伸已有R2参数，支持6条奖励远征及折返、单向环回、汇合；默认参数保持旧行为，原31项拓扑测试通过。没有另写同功能Graph Generator。
2. `block_grid/policy.py`、`plains-policy.json`：保存本轮规模、主线差异、回程和五类奖励预算。数量与价值分开。缺少标定、真人时间、实际Boss和整图物理时均不签完整验收。
3. `block_grid/plan.py`：生成并审查完整职责蓝图，导出Challenge Specifications，调用现有Workshop入口反馈 `needs_design`。当前完整蓝图尚不能自动物化，不能称闭环已覆盖任意需求。
4. `block_grid/catalog.py`、`prototype/plains/block_modules.py`：从既有源内容创作新的Block变体和四向岩井。终端岸体每侧最多扩32px，越界铃铛需迁入内部；调整发生在Module生产阶段，重验新版本，不在Map补连接平台。
5. `block_grid/build.py` → 原 `shape_search.search(require_blocks=True)`：沿用PR#1已有的有限3/4层回环探索图，去掉旧位置，以新形状和端口重新求解。候选有效性、Block所有权、运动profile、真实碰撞、动态包络、动作净空和环闭合一起检查。
6. 原 `direct_join.canonical.export_reload` → `export_modules.mjs` → `module-contract.js` / `module-block-grid.js`：标准Module文档导出、内容版本检查、重新读取，再组装。新掩码和净空不能与标准文档脱节。
7. 原 `assemble_modules` → `BlockEngine(FeedEngine)` → 原Godot Motor / Router / Cell：单角色、连续资源与世界时钟、无中途传送或重建。新增边界审计不改变物理，检查角色身体全程处于预留Block、实际从声明开口穿过，并保存真实速度、落地、射击资源、生命、机关时钟和两端版本。
8. 原 `CandidateLibrary.enroll_payloads/find_payload`：整图方向覆盖通过后进入隔离实例和逐Module payload索引。精确需求命中可以复用，仍重新验整图；一般关系UNKNOWN，人工评审待定，生产库不自动开放。

目前Module选择仍有限：新枢纽1类、适配6份源挑战及其独立镜像，共12份单向挑战变体。实际整图使用尖刺窄槽、限时击铃、移动射线窗及岩井反冲；landing接力虽经过单体测试，未强塞进本轮匹配域。整个94版目录被检索，但未满足Block/净空/内容条件的旧版本不会因“库里有”而自动准入。

## 完整44节点蓝图与真实阻塞

`block-grid-region-plan-v2` 用原R2生成44节点、3条主路线、6奖励支路，含三种回程各两条，五类数量预算6主要道具/12金币点/3恢复/1商店/2隐藏，其中2高价值。**这里只是职责蓝图，physics=NOT_RUN。** 所有奖励尚未物化，价值未标定，不计作实际取得。

具体缺口：r19需要5 Port，现有新枢纽只有4 Port；任意方向穿越和不同跨距的Block库不足；Boss真实战斗没有接入此隔离Runner；现有奖励适配不能把金币包装成主要道具、恢复或持久隐藏收集。Workshop对未注册的block-native职责返回needs_design，尚不能据任意自然语言自动创作这些内容。系统没有删除关键路线掩盖失败。

全区域的意义变化间隔、回报/风险定价、战斗资源压力和人类游玩时间仍UNKNOWN。逻辑无死锁来自既有单调能力/机关状态求解；真实的任意输入状态、消耗型能力及所有意外捷径未获证明。两个同世界省略反冲策略（含延长跳跃）均失败，保留原始失败，只排除这两种简化输入，不是全局反绕关证明。

## 失败和未通过的方向

- 枢纽v1仅9/13：东侧落点位于上层实体下方，角色受阻或越出预留形状；移动模块内部落点后，v2才13/13。
- 源适配v1～v3仅覆盖2/4/4个变体，不是完整12版成功；v4扩至12份后仅4/12。原因包括越界铃铛、镜像共享数组重复翻转、移动窗扫过入口检查点，以及射击目标与新坐标不一致；v5重新产出和真实验证后12/12。全部旧输入/失败均保留。
- 第一轮本地浏览器检查用错期望入口L0，实际Graph入口L1，检查失败原件保留；更正测试参数后WebGL真实移动/跳跃/射击/重试/地图烟测通过，没有改游戏入口迁就检查。
- 视觉仍规整：当前模块内部岸体本来就是矩形，且重复使用同一四向枢纽。Block允许不规则形状不会自动创造不规则地貌。这轮没有证明“稳定超过旧管线”。

## 性能、风险和下一步

8～12ms仅为有限模板、12/16实例的离线Python CSP求解时间，不含库检索、标准文档导出、源绑定和真实验证。三批含11整图策略的流水线实际约117～180秒；这是离线验证成本，不是Runtime生成速度。没有测峰值内存，也没有将Python运行链迁入正式Godot Runtime，不能据小样声称65节点稳定实时。

下一步应先补几个**不同形状、不同职责**的Block Macro：5/6 Port开阔枢纽、偏移出口斜向穿越、以空中击铃反冲为核心的奖励支路、真实折返与单向回程、带主要道具/Boss的终点。每个都明确动作关系和净空，独立验证后才交给同一个CSP。之后以完整R2需求联合搜索，遇到不可满足核心反馈Module Generator，不先把同一个岩井重复十层凑40个。

验收应保持双门槛：技术上零补路、接口与整图方向合法；设计上地貌轮廓/空间节奏/挑战关系确实有差异、主支收益合理，并有真实视频观感或试玩证据。仍以当前主游戏的协调感作为对照，不能仅凭33条通过就宣称新图更好玩。
