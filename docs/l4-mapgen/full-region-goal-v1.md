# 从风谷样品转向超过正式地图规模的完整平原

用户本轮明确指出：人物、移动平台等仍未迁移完整；下一目标是比当前主游戏原版规模更大、更有趣、更合理的整地图。8个Module风谷从此仅作为机关/接缝/表现回归样品，不再计为大图目标达成。

## 真实基线和验收目标

最新map-edit main仍为b9318cf，主游戏正式main为26e7f2a4，较新integration分支84957e35仍是单独开发线。`full-region-baseline-sizes-v1` 用正式v12配置，对5个共同Seed分别生成intro/advanced，10张完整正式地图实际为20–23个探索地点、58–68个Module实例。首次单图目标以这组最大完整地图作对照；两图战役的总量另列，不能把单张新图与两张旧图混算。

目标合同在 `pcg/map_directed/region_scale/protocol.json`：至少32个有探索职责的核心地点，内容实例预算96–128。预算不是品质得分，不能通过拆碎Cell或重复同一房间完成。有效路线长度、已填充的探索空间和独立挑战段落也必须增长；单独扩大外接框/空中留白不算规模增加。

四个平原内分区：风车群落（空中击铃/反冲落岸）、钟楼上廊（净空/错层与可见地标）、回声溪谷（移动平台/相位/深支路）、悬索岩壁（垂直回程与高风险宝库）。分区共用基础设施，但动作关系、空间比例和回程职责不同。

主线保持简洁：前庭前4–8个探索转移，不铺固定横向直达脊线；至少两条有明显差异的初访接近路径。奖励支路更深，须有实际宝箱、不同入口/汇合和有收益的返程捷径。难度节奏包含读图、行动、恢复、选择；机关数量和环数不能代替这些职责。

## 本轮人物与平台问题的实际修复

旧样品只调用UnderworldActors.install，这个函数安装敌人，**不会安装主角**。主角仍走旧CourierVisual。另一个明确错误是样品对平台调用set_painted_enabled(false)，因此主动走回旧皮肤分支。

新增formal_style.gd复用主游戏 `PlayerPresentationRuntime.make_body(...,"courier")` 和attach：实际实例为PlayerMotionCandidateVisual，旧CourierVisual只保留权威枪口并隐藏；同时保留原PlayerFeedback以供正式MotionFeel/WeaponFeel合法依赖。原PlayerWeaponFeelAudioV2存在后，正式动作/武器表现才会安装；不会悄悄跳过该分支。平台启用真正UnderworldCarrierPaint，实际纹理读取自原机制构建JSON。

14份关键主角/动作/武器配置、移动平台、Tile、射弹及源图逐SHA与main相同，见 `pcg/research/formal-style-main-binding.json`。870保护原件未修改，补齐了动态加载音效的原件/导入资源闭包；不通过改角色坐标、资源或射线使旧见证继续成功。

5条连续风谷路线重验通过，角色/武器/动作/平台的实际节点回执全部通过。修复后的停靠回程原生录像与新物理回放1662帧一致。该录像仅证明美术/接口修正，**不是新的大地图成果**。

旧/新运行的完整轨迹比较并不相同：正式角色安装器会更新权威枪口，第一枪枪口从[104.5675,791.7095]变成[103.1050,793.7345]，命中时机及敌人回程轨迹也会变化。因此没有把旧结果续签成新通过；5条路线重新真实执行，录像对照新的物理结果，差异原件保留在movement-regression.json。

当前隔离Harness仍以12f6cb0物理绑定；尚未签整个主游戏表现/战役接口全部迁移。已知旧UnderworldEnemy受击模板、Boss受击呈现和前景调度与正式main有差异，完整大图应使用正式运行时整体消费或明确版本化适配，不能将本轮14项匹配扩大成“全游戏所有表现已一致”。

新样式采用显式 `--formal-style`，历史批次继续按原字节和结果保留。完整大图尚未可玩，后续验收必须补齐真实空间、内容和全图证据。
