## 算法实际读取什么

调用路径：`shape_search.run.build → catalog.load/reload_catalog → search.search → canonical.export_reload → direct_join.assemble_modules → direct_join.audit → prepare_cases → ShapeEngine/CompleteEngine → 原Godot Motor/Router`。

`catalog.py`读取标准文档绑定的实际物理payload：碰撞矩形联合形状、local port/normal/aperture、关闭门体、齿轮扫掠、实际父版整图身体轨迹。旧world placement交给搜索前清为0，不作为提示或fallback。

`search.py`为有界CSP：Seed决定候选顺序，优先放置已放邻居最多、最早闭环的节点；用端口反推出位姿，同时满足所有邻居的闭环方程，依次检查真实开口能容纳24×36角色、实体/门体无未声明重叠、动态扫掠不进入邻接实体、动作身体样本不被邻接岩体阻断。单向平台保留由下穿越语义；只有双方显式声明的同一个shared landing可以同形覆盖去重。最多50,000扩展，输出可行/不可满足/预算耗尽、拒绝原因、放置/回退记录和绑定。

本轮动作条件是落地停稳dock、空射≥1、冷却0、速度≤1；缺能力或进入资源不符会拒绝，真实世界每次Module动作进入重新检查。它还不是高速空中交接或连续状态集合传播求解器。父版身体轨迹每2tick采样，仅用于筛查，不是完整净空或变体证明；lookout/east没有父版module-action样本，明确不补造。每张新图都重新运行完整世界，不能继承单Macro成功。

选择规则是第一个可行解，**本版还没有地貌/美感目标函数**。

## 库存自由度与诚实的多样性

最初8个刚性Macro只有原布局与全局镜像两种闭环。随后只对lookout/hollow两个恢复岸提供有限宽度/高差变体，挑战核心不缩放；变体先创建、版本化，再搜索。48个初始候选中6个低岸镜像因齿轮扫掠越界剔除，实际42个。去掉west/ridge共3块已退役旅行门的无用途顶盖。

新版本通用关系仍UNKNOWN，只允许隔离实验和新整图验证，不入生产库。原端口ID绑定图边、角色互换不足，导致五Seed只有4个空间签名；去镜像仅3种岸体组合，Exploration拓扑只有1种，不能称五种探索体验。

## 消融及实际物理反例

同42个候选：AABB拒绝5/5；shape-only及shape+action可拼5/5、每Seed答案相同。因此只证明真实轮廓避免矩形过度拒绝，不能说动作净空已提高正常样本成功率；AABB消融也不是旧正式游戏算法。

故意破坏一个完整世界：按确定性规则选择第一处位于邻接Macro核心内、不碰既有实体的真实身体样本，在邻接Macro加20×20岩块，端口不变。shape-only放行、静态审计通过；shape+action以 `actual_action_space_blocked` 拒绝；同图原Godot主线427tick后 `landed_on_unexpected_support`，实际落到新增支持面。见 `shape-search-action-obstruction-{source,physics}-v1`。这证明动作数据真的参与约束，但单反例不是普遍质量优势。

## 未通过原因

- eval2/eval4入口反冲扰动错过落点、`leg_frame_budget`；旧布局相同扰动也失败，是继承的挑战/策略余量不足。
- eval3奖励远征齿轮处受伤，配对旧布局通过，是新岸体/状态组合额外回归。扫掠边界合法与静态动作样本避让不能证明动态相位策略安全。
- 这些是固定策略失败，不等于人类无法通关，但足以使鲁棒验收不通过；失败后未换Seed、调几何或重跑挑通过。
- 校准失败另保留美术依赖缺失、恢复岸错误替换原相位策略、动态扫掠越界、镜像回程受伤等；技术修复均在独立评估前。
- 首次Seed0录像的JSON比例轴输入往返产生约2.4e-7位置差，严格比较失败并保留原件。后续沿用原录像器，执行与headless相同冻结Router策略，避免双精度轴输入序列化；未放宽任何比较。Seed1普通输入回放也严格通过。
