# 可追溯录像与观感审核

用户偏好短视频下载与聊天反馈，不强制网页表单或亲自试玩。视频帮助判断可读性、节奏、动作关系和重复感；它不替代真实 Godot 认证、实际试玩或生产认可。

先读 [MAP_FOUNDATION.md](../../../MAP_FOUNDATION.md)、[MAP_GENERATION_GUIDE.md](../../../MAP_GENERATION_GUIDE.md)、[迁移状态](../../../pcg/migration/foundation-v1/status.json)及[Module迁移skill](../pcg-module-migration/SKILL.md)。按[物理合同](../pcg-physics-contract/SKILL.md)界定证据范围。当前生产暂停，只为本仓库、随后主游戏已有内容做迁移与重验，不借录像流程新增 Module。

当前实施采用最新已授权迁移顺序与三去向：先本仓库、后主游戏；技术合格可复用内容入根 `modules/`，事实已确认的完全重复非代表项/明确排除项入 `modules-recycle/`，近似待审、缺口或验证失败留原处。目标验证与回读、引用及可恢复归档检查完成后才归档原件，不提前搬走失败源。技术认证与人工观感/试玩/生产认可分开；旧Map生成器退役，本轮不实现新Map、不commit、不发布。工具能力以实际实现和回执为准。

## 1. 先定影片代表什么

录制前确认真实场景/消费者、冻结输入和源绑定。每段 manifest 至少保留：

| 身份或证据 | 必需信息 |
| --- | --- |
| 基础内容 | `base_module_id`、内容版本、Foundation 版本、场景/源码 SHA、引擎 SHA、游戏源提交 |
| 放置方向 | `orientation` 或明确 `mirror_x`；原向/镜像共用同一基础模板身份 |
| 实例用法 | `connected_port_subset`、`closure_profile` ID/版本/SHA、被封 Port 列表；无封口也显式写明配置 |
| 真实路线 | route ID、from/to 真实 Port、初始权限/地貌、初始条件和离线进入/离开合同引用 |
| 原始实验 | case SHA、physics run/原 raw SHA、策略/输入 SHA、原生 trace SHA、比较字段/方法、比较结果与全部差异 |
| 媒体 | MP4 SHA/字节、原生帧数、帧率、时长、播放速度、片头/尾停留/剪辑区段、用途与审核类型 |

新字段表示应当绑定的语义，不代表旧 recorder 已支持它们。缺少真实基础身份、方向或封口证据时标为 `legacy / migration_pending / UNKNOWN` 并说明 gap，不编造默认值或给旧影片重贴“新地基已认证”标签。保留旧 manifest 原件，新迁移索引单独引用。

同一 Module 的多个 Route、同一有序对的不同策略、自环 A→A、镜像与部分 Port 用法可以各有影片；它们不是多个基础模板或新玩法家族。内部 staging、goal 框或 Harness marker 不是真实边界 Port，不能通过镜头标签制造合法接口。

## 2. 录制真实动作与时序

复用既有 recorder、movie scene 和原 Godot Harness；以仓库实际绑定的官方引擎二进制运行，独立显示环境、原生60Hz、正常1倍播放。不要用网页预览、插值动画或直接设置玩家轨迹代替实机输入回放。

从冻结 review cases 连续录制，保留关键等待、失败、恢复、回枪、门重闭和出口稳定过程。用实际动作/场景事件核对路线，不能因为展示目的不同就改几何、输入或资源。原始完整片与 trace 保留；短节选或合集注明起止时间、移除的内容与拼接位置，不将删除验收尾段误报为玩家等待，也不剪掉设计中的等待来提升节奏评价。

片头、末尾冻结完成画面或字幕必须明确，冻结时整个世界一致。区分原始物理帧数、最后帧索引、媒体总帧数与尾停留长度。一次录屏包含多个策略时保留它们各自的身份，不能跨版本拼成同一连续成功。

ffmpeg 用于编码、压缩、明确标记的裁切或合集；保留时序，不加速后仍标1倍。ffprobe 检查尺寸/帧率/时长/格式；用抽帧和实际看图检查可见性、目标、Port与封口。不只看日志便宣称已看过影片。

## 3. 比较实际 trace，不放宽失败

按原严格比较器逐帧比对位置、速度、输入、资源、伤害、接触、机关、敌人与事件，绑定 case/module/source SHA。确认场景与验证器使用同一真实角色表现及枪口；视觉 pivot 若影响实际枪口，不能当作无物理影响的换皮。

全部差异随 manifest 发布，原失败保留。`support_id` 或一帧速度差异仍是严格失败；即使金币、终点、截图相同，也不能改称 exact。允许另供明确 `review-only` 影片作观感材料，公开比较失败和枚举差异，不能将其计入严格一致影片数量或替代技术证据。

已有比较器对某些源字段有明确的进程 ObjectID 归一化时，精确注明字段与既有规则；不新增宽容阈值、不删除 support_id 或事件来救过。不通过重写 raw、trace 或历史 manifest 修正失败。新增只读字段对照应单独出审计，不能反写原比较器的覆盖范围。

纯表现修订保留原场景、片段和版本记录，使用显式新 consumer/scene 绑定重新录制并与原 case/raw 比较。只有确认执行物理/输入未改，才标注为同 case 的表现版；它不增加基础模板数、独立校准样本或新玩法数。表现导致枪口/碰撞/策略变化时按新内容版本重验。

## 4. 展示新地基的实际结构

画面能识别整个矩形 Module 的空间关系、实际端口、被测路线与未用 Port 的处理。矩形范围可用调试辅助显示，但游戏不要求外框。Port 标签使用真实边界点，避免 goal 框遮住 Port ID；展示内部 dock 时明确不是 Port。

审核至少看以下内容：

- **Port 语义**：AIR/ROCK/ONE_WAY_PLATFORM、边界朝向和初始 INPUT/OUTPUT/INOUT 与被展示方向一致。初始关闭/单向门的运行后变化不冒充初始双向权限。
- **部分使用与封口**：清楚标识 connected subset 和 closure profile；未用口的封口真实存在，不靠镜头裁掉开口。少量伤害或视觉荆棘不等于已封闭。影片仅见封口不能证明全部穿越尝试失败，仍引用离线认证。
- **有向 Route**：N×N 包括自环，正反向独立。A→A 必须是同一个真实 Port 的完整进入/返回；旧虚拟 marker 循环不算。没有对应影片不意味着无路，有代表片不意味着其余版本/方向已录证。
- **镜像**：同 base 下完整镜像 Cell/碰撞/机关/视觉与左右行为，Port 权限语义不反转、Route 矩阵不转置。仅将画面水平翻转不能当作镜像物理认证。
- **真实额外通路**：拍到未规划但真实可行的通路或奖励绕法要绑定证据并反馈认证/实际图，不能因 planned route list 没列就剪去或声称不存在。
- **边界与动态实体**：静态 Cell/环境碰撞/封口布局受矩形约束；玩家、敌人 AI、弹丸的运行时运动不等于矩形占用重叠。玩家经未启用开口离开属于接口/封口问题，另行记录，不混写成静态重叠。

资源、速度、生命和机关事件是离线动作合同及运行时证据；不因视频包含它们便要求在线 Map 逐步追状态。在线只用生成初始能力、初始权限和已认证 Route。开门后返回如属于特殊完整玩法，影片绑定该完整结构，不能替通用初始图补一条未开启边。

## 5. 审核类型与反馈循环

始终区分：

1. **技术比较**：原生回放与物理 raw 的字段一致性及明确失败范围。
2. **AI 观感/去重**：实际查看了哪些影片或抽帧、所用当前会话/子代理身份、具体模型版本未暴露时如实写未知；观察玩家决定、动作—世界因果、路线成本和恢复，不能只按动作词或技术pass分家族。
3. **人工视频观感**：真实用户看影片后的节奏、可读性、重复感与兴趣反馈。
4. **实际试玩**：有人真实操作后的手感、理解与难度证据。
5. **生产认可**：独立明确记录，技术通过、AI肯定、整体批次正向反馈都不自动等于每个版本获准生产。

收到意见后保存用户原话、稳定反馈ID、影片编号/视频 SHA、base/版本/方向、Route、connected subset/closure profile 和拟修订问题，类型标为 `video_observation`。AI解释与原话分开，不编造评分、通关率、试玩或批准。用户可直接聊天反馈；观感未审不阻断既有候选的迁移实现与离线实验，但当前新内容生产暂停规则仍适用。

先描述看见的实际行为，再区分推测与待验证项。真实失败、无聊、读不懂、廉价解和重复关系反馈到迁移优先级/设计修订；合理替代保留。返工涉及源、地貌、Port、封口或策略时新版本重绑并按物理合同重验，旧片不覆盖。

## 6. 发布与迁移完成条件

本地 MP4、仓库归档、可公开下载链接分别记录。只有实际上传并从公网下载核对字节 SHA 后，才称链接已发布/可下载；不把本地路径或 Pages 索引存在当作公网核验。此 skill 不自动授权发布操作，遵循当前任务范围。

交付短片及可复核 manifest、native trace/原 physics 引用、源码和完整失败，按 base 模板汇总方向、用法与 Route，分别统计 strict、review-only、表现重录、未录覆盖。代表片只解释共享玩法，不能替其他内容版本充当回放证明。

新地基迁移完成需对应结构、工具和真实认证均落实。旧影片仅能解释其旧版本；格式转换、封口标签、镜像索引或新版 skill 本身都不增加新地基认证数量。尚未支持的新 Port、真实边界自环、封口组合或镜像比较明确列入迁移 gap，交给既有工具逐项补齐，不发布为已认证能力。
