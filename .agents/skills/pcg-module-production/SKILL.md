---
name: pcg-module-production
description: Maintain the single current Module source library, atomically revise or retire content, and build a versioned portable Module package with real Godot evidence.
---

Use this skill for all current Module authoring and distribution. Tell the user when applying it. The user's current scope and authorization take precedence over historical session restrictions.

1. Read `AGENTS.md`, `MAP_FOUNDATION.md`, `docs/module-production.md` and the affected `modules/<ID>/record.json`. The only current records are those generated into `modules/catalog.json`; never infer the latest implementation from an old round, branch, handoff or file timestamp.
2. Preserve stable identity. Add with `python3 -m module_pipeline add INPUT.json` (allocates `module-<UUID>`), or supply an explicitly allocated `--id`. Designs use `pcg/module-design/v1`; their preview is rendered by the existing renderer. Implemented documents use Foundation generationContract v2 and native runtime bindings. A new ID starts in development, not runtime-ready. A human-kept but unimplemented design remains visible.
3. Change the same ID with `python3 -m module_pipeline update ID INPUT.json`. Edit actual objects and their declared bindings; never hand-edit compiled geometry, thumbnails, versions or catalog rows. The transaction stages all files, checks the entire index, then atomically exchanges the library directory. Failure retains the old library. Updates lose implementation/portable approval; gameplay or runtime-contract changes also lose route qualification. A metadata-only revision can carry route evidence only through the tool’s explicit content-equivalence attestation. Record exact-version feedback with `review ID --version sha256:… --decision KEEP|CHANGE --note …`; KEEP does not fabricate physics evidence.
4. Recheck affected current inputs with the existing native qualifier and causal/quality gates. Freeze current source/program/protocol before execution; independently bind calibration/holdout/boundaries and accepted actions, not requested inputs. Evidence inputs belong under that ID's `validation/qualification/`; temporary experiment outputs are generated data. `qualify ID --evidence ADMISSION.json` invokes the existing deep raw verifier, rejects wrong versions and incomplete routes, and then records scoped qualification. See the exact admission format in `docs/module-production.md`. Historical pass flags and load-only smoke checks do not qualify changed physics. Do not reroll an observed holdout or quietly weaken thresholds.
5. Retire with `python3 -m module_pipeline withdraw ID --reason REASON [--replacement ID]`. It removes source/runtime payload from production, retains the ID tombstone, and preserves uncommitted content in an immutable content-addressed archive. Never recycle stable IDs. An exact duplicate needs measured payload, loader, footprint, Port, Route and capability equality; similar titles are insufficient.
6. Rebuild views with `python3 -m module_pipeline index && npm run build:workshop`; verify with `npm run check` and relevant production tests. Official refresh reads main. Pending/withdrawn state must remain distinguishable from runnable delivery.
7. Commit current source/tool/runtime inputs. The fixed delivery command is:

   `python3 -m module_pipeline build --version 1.1.0`

   Choose a new SemVer for changed contents. The command validates the unique library, rejects empty delivery, resolves/checks dependencies, extracts a candidate ZIP into a clean host, uses the hash-pinned real Godot and `strace` file-read audit when qualification is absent/stale, records evidence and emits `releases/map-edit-modules-<VERSION>.zip` plus SHA256/metadata. Already matching evidence can be reused; `--revalidate` reruns native acceptance. `--host-source /path/to/locked-host` uses a verified local cache; omission installs the pinned dependencies from their upstream commit. Package contents have fixed timestamps and sorted paths. Existing versions cannot be overwritten with different bytes.
8. Inspect actual files/results. Report current counts from the catalog, exclusions from the package, source commit, version, checksum, download link and supported configurations. Distinguish pinned-host local qualification, latest-game API compatibility, arbitrary seams/chaining, mirror/relocation/closure and human playtest. Publish only within the user's authorization; a reviewable PR and real nonempty package are required when requested.

Required tools: Linux/Python 3.12+, Node 18+, `strace`; exact Godot 4.7.2 is found by hash or installed into the user cache. No credentials belong in the package. Source archives, old rounds, films and raw traces are excluded from runtime delivery.

Current and future output rules: export complete existing `reward_sites` with stable IDs, position, claim region and amount. Reuse only Route `resourceProfile.requiredRewards`; a missing export association may be projected from exact qualified native case `required_rewards`, never inferred. Generate the reward-association gap report each build and retain unconfirmed modules/chests. Do not reintroduce per-module mirror eligibility flags, mirrored copies or an all-Port connection requirement. Original configurations are evidence witnesses, not a generation whitelist. map-gen owns complete-content mirroring, connected-Port selection, unused-Port gear closures and remaining-route checks; new configurations stay UNKNOWN until checked. Mark Boss purpose through `purpose` and derive the same ordinary `entryPortIds` field from directed routes/ingress permissions. Do not create a parallel reward, Boss or routing contract.
