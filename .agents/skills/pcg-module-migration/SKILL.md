# 当前任务与依据

先读根目录 [MAP_FOUNDATION.md](../../../MAP_FOUNDATION.md)（Normative，最高模型依据）、[MAP_GENERATION_GUIDE.md](../../../MAP_GENERATION_GUIDE.md)（Recommended）、[AGENTS.md](../../../AGENTS.md)、[WORKSPACE.md](../../../pcg/WORKSPACE.md)、[OUTPUT-CONTRACT.md](../../../pcg/OUTPUT-CONTRACT.md)及[迁移状态](../../../pcg/migration/foundation-v1/status.json)。Guide 的库数量、尺寸、Port 数、路线数和算法是推荐，不自动成为准入门槛。代码、旧文档和旧 skill 不覆盖 Foundation。

当前已授权**执行既有内容迁移**，不是继续新增 Module 或实现新 Map。顺序为：**先本仓库已有 Module，再处理主游戏已有 Module**。保留主游戏机制作真实参考，不破坏正式游戏资源/流程。若历史 status 或报告仍写“主游戏优先”，明确记为待同步的旧状态，不按旧顺序执行。

旧 Map 生成器退役，不恢复其生产入口、不修回旧不规则空间模型、不启动 N26。当前对**全部**已登记来源执行实际修正和验证，不停在10件试点。先本仓库134个既有候选版本，再主游戏资源及已登记样品；版本、镜像、参数样品和引用副本不能都计为独立模板。无法保留核心玩法满足时才据真实修复/实验记录留待处理。

# 三个去向

| 去向 | 条件与含义 |
| --- | --- |
| 根目录 `modules/` | 达到当前技术迁移契约的可复用内容及可追溯认证；人工观感、试玩、生产认可分别记录，技术合格不伪称人工批准。 |
| 根目录 `modules-recycle/` | 成功迁移并完成目标验证/回读后归档的旧原件；以及有明确事实依据的非代表完全重复项或迁移计划已明确排除的内容。保留来源、理由、替代项/alias与引用去向，不是物理失败的自动垃圾桶。 |
| **原处待处理** | 实际适配后仍失败、证据不足、近似重复待审、无法保住原核心玩法，或者去向尚不确定。缺少通用尺寸/Port适配、既有Cell导出映射或消费者支持是本轮要补齐的工具任务，不能据此直接终止该类迁移。原件、失败与依赖原处保留，不假装完成。 |

先形成有依据的分流记录，再执行支持该操作的实际工具。不能仅凭 AI 觉得无聊、名称相似、镜像、大小或动作词相同就搬入回收；近似项保持待审。正式目录不等于自动获得人工趣味或游戏生产批准。

# 每件内容的最小修改流程

1. **审计来源与引用。** 列出真实场景/文档/Cell/代码/媒体/原验证与依赖、稳定 ID 和原 SHA；区分基础模板、版本、镜像、多个 Route、历史副本和失败样机。先本仓库，后游戏；不要凭旧库数字推断可迁移模板数。
2. **检查原物而非只读说明。** 保存用户原话、既有负反馈与成功替代。描述玩家观察/决定、动作—世界因果、所需能力、奖励、失败恢复与各向差异。保留有用核心，不把旧标题下的基本走路当迁移成功。
3. **给出并执行逐项最小修改。** 将 Foundation 检查分为已满足、可复用证据、必须修改、待实现工具与 UNKNOWN。按真实地貌及必要动作空间向外取整至128倍数，不保留无用镜头边距；先整体平移对齐多个Port，再修接岸/端点支撑或必要短连接。不能只移动标记、不改实际支撑和出入动作，不能新增绕过核心挑战的安全通道。需要改几何/Port/封口/镜像/策略时明确新版本、影响范围及重验，不全局缩放、加外框、强制动作或改成新家族。
4. **冻结后验证。** 使用现有真实 Godot Harness、角色/弹丸/承载/资源组件、原质量门槛与固定预算，不复制模拟、另建验证框架或降低门槛。验证版本、方向、每条 Route、实际入口出口、封口组合、允许镜像及必要接缝；原失败与 raw 不覆盖。静态转换不替代物理认证，单 clean 不签通用恢复/回程。
5. **精确去重。** 对内容与接口语义完全一致者采用可审查的确定性比较或明确等价证明，选代表、保存 alias/引用迁移；不能仅凭不同文件 SHA 或相同标题判定。镜像是同 base 的方向变体，不是 Route 转置。近似重复保留独立证据并列待审，不自动删除或沿用代表项技术资格。
6. **写入候选目标并回读。** 使用实际已实现的迁移工具，核目标工件完整、来源/依赖与 SHA 可追溯，实际运行必要验证并检查结果。技术失败、未运行、工具不支持或证据缺失均不 promote 成通过；回执明确 NOT_RUN/UNKNOWN/失败范围。
7. **验证完成后才归档原件。** 目标完整性、技术结果和引用接线完成，能从目标重新加载且归档可校验/恢复，才允许原件归档。不得提前搬走或删除原场景、raw、源与依赖来制造迁移完成；失败留原处。归档包/索引/分片及还原 SHA 明确绑定，不凭“已打包”替代验证。
8. **构建库并汇报。** 仅将满足技术要求的实际迁移记录编入 `modules/` 索引；回收和原处待处理分开。统计 base、镜像方向、版本、Route、完整重复归并、近似待审与失败，不用格式转换或影片数当完成数。

批处理按机制/能力/运行时分组，复用原Harness和冻结源；新版本完整认证一次后，以不可变工件SHA校验复用，不在每次入库时重跑全库分析。批末统一编译索引。人工设计hold项仍修格式并保留hold，不自动批准或默认供检索；可选接口认证不阻断原配置迁移。

旧Port的默认朝向若只是未认证设计提议，不把它当不可变真相：按实际路线出流、附近合法边和最小接岸修改选择，并明确旧值、新值与理由，重验真实接口及路线。不得为了维持一个未验证的RIGHT标签铺成长安全底板。已经认证的当前接口不能据此静默转向；它的可选换边按完整配置认证。

原奖励台/中途dock与新矩形外边Port分别命名。原`via_ports`若实际含义是访问内部奖励台，迁移为明确`source_via_ports`来源、命名`via_waypoints`及真实站位/trace检查，保留原因果验证器要求；不能删除访问条件救过，也不强迫玩家为标签走到远处外边再折返。实际Route端点与真正外边通行不得解释成内部waypoint。

组合Macro的门时序、下落刹车与返回阶梯往往共享原岸高；泛化量化原岸后失败时，优先恢复原核心平台/机关/奖励/输入，用独立的小外缘落脚台和经过真实跳跃/反冲验证的间隔接入，而非铺贯通安全底板。实际例子为正式库 `workshop-macro-gate-brake-return-0/1`：全部9块原平台及核心程序不变，3个局部外缘dock，4条路线/双向端口与连续进出重新验证，两个子定义重新绑定。内部子定义未独立认证，不冒充额外正式Module。

正式qualifier/full_campaign先执行 `pcg.migration.holdout_guard`。同原`sourceVersion`下已观测的真实留出条件不能因改Module名、Route名或自行换seed再次称为新独立留出。纯观测器、打包或未改变真实几何/动作的标注修订优先对原raw只读重分析并重绑测量版本；只有校准失败且尚未看留出时，才按预登记预算做≤2修。真正改版需要独立池时，先冻结候选、按工具实际能力预登记并验证Harness真实采用该协议；不能把“登记成功”或不同seed当成执行证据。已存在通过报告可重验/重放/打包，不重复消耗新留出。

# Foundation 必检清单

- **空间：** W/H 为正整数 Block，默认128像素且可配置；占据完整矩形，实例矩形不重叠。内部 Cell 可像素级不规则，静态布局/环境碰撞/封口在矩形内；不把玩家、敌人、弹丸运行中移动等同静态占用重叠，不画强制外框。
- **Port：** 在矩形外边 BoundaryBlock 外侧边中心；锚点与完整身体 staging 分开。连接要求世界点重合、法线相反、surface同类、初始权限兼容及接缝认证。ROCK仅左右且有安全实体岩体；ONE_WAY_PLATFORM四面可用且有安全可穿支撑；AIR按认证向下进入，底边不得具有INPUT（包括INOUT进入），顶部AIR OUTPUT没有合法同类底边INPUT，不能当必接向上出口。
- **权限与 Route：** 初始 INPUT/OUTPUT/INOUT独立声明；N×N包括自环，每格0或多条Route，正反向独立。Route记录位移、能力、动作、难度、时长、资源、初态、动作接口和validation；自环需要相应进入/离开权限，不能用内部marker假造。真实额外有效Route不能按规划删掉，未认证迹象要列缺口。
- **部分连接/封口：** 不要求模板口数等于实例连接数。每个未用口有本Module内认证封口；仅扣血或视觉障碍不合格。封多个口不破坏保留Route、不造新通路，受影响配置分别认证，不能默认所有子集均支持。
- **镜像：** 同base方向变体，全部Cell/碰撞/Port/机关/方向行为与视觉一起镜像。格x'=W−1−x、双倍边坐标u'=2W−u；左右face交换、权限与起止身份不交换，矩阵不转置，只开放认证方向。
- **角落Port换边：** 执行[角落Port扩展](../../../docs/l4-mapgen/corner-port-relocation-v1.md)。逐Port记录`cornerRelocations`四角属性，目标只能是同一角落Block另一外边中心。允许局部支撑/地貌类型适配，但不得改变原核心玩法、初始权限、必要能力/资源要求及原有路线功能。`allowed=true`须绑定当前版本、完整配置、真实Harness证据；未测UNKNOWN不可匹配。原位置与换边互斥是逻辑接口选择，不要求封住旧几何开口，也不为换边额外加墙；旧位置不属于另一个未连接Port，Map须另验开放几何的相邻影响。多个换边仅开放已联合认证配置，镜像不自动继承。ROCK不能直接转为上下口；需真实合法可穿平台和证据。所有来源顺带判断，但可选换边失败不阻断原配置入库。
- **在线边界：** 以后在线仅纯程序读取已认证库、一次静态能力与初始权限，不追踪HP/精力/速度/背包/机关步骤，不在线LLM补Module。本轮不实现新Map。资源与运动仍是离线真实认证和运行时职责。

旧验证器缺少上述字段或行为时，具体报 gap，不改历史pass标签，不通过新增JSON字段宣称已实现。继续复用现有库/源绑定与 Harness；新目录承担迁移交付，不是复制一套候选搜索或物理。

# 命令与证据边界

预期统一入口为 `python3 -m pcg.migration audit|inspect|validate|promote|archive|build`；`|` 表示子命令选择，**不是可直接复制的shell命令**。先检查当前源码/帮助确认实际已实现的子命令、参数和验证覆盖，再调用；本文不宣称这些功能全部可用或任何内容已通过。`audit/inspect` 不等于认证，`promote/archive/build` 不能绕过前述前置条件。不使用旧生产CLI代替迁移工具。

每件交付来源/目标、修改diff、版本与SHA、执行命令、真实输入输出、校准/留出/反例、失败/UNKNOWN、目录去向、归档/回读证明和依赖引用。技术认证、AI分析、人工视频观感、亲自试玩与生产认可分栏；未人评不阻断技术迁移，也不自动升格认可。不commit、不发布，除非另有当前明确授权。

## 原游戏来源的行为绑定补充

先区分源的普通`steps/routes`、H/R程序、`approach_steps/action_start/departure`、命名司机及奖励返回；不能用一个“先跳后H再走终点”的策略替代这些不同职责。原世界以普通路线使用且明确允许无H的分支，不从`action_program`字段推导H必要性；专门H见证仍检查真实接触与目标序列。输入请求未被原机制接受时，不算已经执行的射击/跳跃；当前1空中弹药下的原司机替代动作须绑定原真实条件和实际接受事件，不能隐式补弹。

下落路线可能在途中被原单向平台承接；复用原司机每20tick的真实Down输入穿过中间支撑，保留平台与落地。先核接岸是否挡住原出沿/关键枪线，再修控制策略。新观察触发器必须接入原DSL实际调度（如带有效`state`），并从真实raw证明输入发生前条件成立；字段存在和合成单测不足以证明触发生效。

区域二选一奖励与Coin/Note拾取是不同原生消费者。保留原`_reward`金额、零金额、tier（包括`hard_optional`）、真实modal选择、同chest ID接受事件及实际Wallet/Meta变化，不能将OR变成两个独立拾取物。原模块作者声明、原世界实际安装与离线新增消费者绑定分开记录；世界中未安装不等于物理不可行，也不冒充世界已跑通。奖励台、失败点、回归点等内部命名先核实际语义，再决定真正外口和独立Route，不为标签强迫奖励后爬回无关高位主线。

新来源进入实验前先比较完整原`data`与真实物理/接口语义。不同factory导出完全相同的数据时，保留代表+来源alias，不为别名重复消费同样留出条件。若重复是在真实实验后才发现，两次运行都是事实，但后者仅为重复实测，不能增加独立玩法或独立留出资格。迁移中的具体行为decoder/消费者缺口继续实现，不归类为“物理不可能”。
