# 获准的新 Module 生产循环

先按 [共用工作流程](module-workflow.md) 确定当前授权。本参考适用于新生成；既有修复/确认设计实现采用工厂 skill 的修改流程，不为修一个候选启动批量创作。下列 CLI 和默认小样域来自既有示范实现，调用前核当前源码/帮助、配方/消费者支持、协议绑定和预算；不因文档存在就恢复暂停生产。

目标是把“做出一个有目的的可玩 Module”变成固定流程，减少每个创意重新搭实验的成本。它不能保证每个提案有趣，也没有在线模型创作服务。

## 两个相互交接的循环

**设计循环由 Codex 执行**：读人工原话/Map Challenge Specification、已产出家族和失败记录 → 选一个尚未覆盖的决策关系 → 写可证伪的设计卡 → 检查原 Cell → 缺少机制则报 gap；可实现则补隔离生成规则及目的/反例检查。完成代码与预注册预算后，停止编辑，进入程序循环。

**程序循环**：完整需求匹配与原库检索 → 原合同预检 → 固定小批动作候选 → clean → 每个通过者等量6次 mild → 按成功数、原程序顺序选一个 → 廉价反例 → 原12次/级别校准 → 冻结选项和精确发布见证 → 独立留出 → 原标准文档/候选库 → 磁盘重读 → 视频审阅队列。

需求或规则不支持时返回 needs_design / unsatisfied，保留具体缺口。廉价反例成立或完整门槛失败时结束该提案，进入下一个不同提案；不在一轮里连续修改到“终于过了”。需要修订时写新源码版本和新预注册批次。不要从留出挑更好看的初始相位。

## 设计卡必须回答

1. 玩家先观察什么、做什么选择，结果怎样改变位置、资源或世界。
2. 主要动作与机关/敌人的因果关系，以及不执行它会怎样。
3. 原 Cell、能力、弹药/精力/冷却、实际恢复条件。
4. 地貌为什么使这个关系成立，完整身体空间、端口及所需范围。
5. 奖励如何被看到和真正领取。
6. 失败成本、恢复、回程及明确尚未验证的方向。
7. 最便宜的反例，尤其普通跳、地面预射击、少打一枪、原地等待。
8. 与既有内容的体验差异；父家族和新的关系假设分别列出。
9. 实现路径、固定搜索域、每接口候选上限和成功/失败判据。

设计卡只是提案。`implemented=true`、新的动作词或标题不注册能力；只有真实生成代码及机制接入能进入程序循环。人工创意入口继续用 `workshop.intake`，保留原话和稳定ID。

## 已有示范的小样域与停止条件

下列候选数和轮数是既有生产循环的默认配置参考，不覆盖当前任务的预登记预算，也不要求迁移/确认设计采用相同搜索域。实际质量门槛以冻结协议及原检查器为准。

- 每轮最多2个接口，每接口最多4个控制候选；小样6次 mild 至少5次通过才继续，**这不是 regular 准入**。
- 每接口只选1个方案做完整校准；最终仍为原 POLICY：12次 mild/moderate，动态内容12次 clean。失败不改 precision 名字过关。
- 反例必须早于完整校准和留出。每个新关系另有针对性反例，不能只套通用18次普通跳。
- 发布用精确 clean 见证的初始敌人相位；它在反例和留出前已经确定。父候选留出跨相位，不冒充每个固定相位都单独达到同样统计。
- 每个冻结轮次复用一个 WorkshopEngine；不改共享 Harness，不复制物理模型。过程中不要改冻结的 Python/Godot/JSON 源，原保护会中止运行。
- 复用原共享 `pcg/map_directed/library/candidates`。原检索后加完整机械需求检查；资源、端口、风险收益或 objective 变化不允许粗索引误命中。
- 同规则源码和需求的失败写入现有 `pcg/feedback/workshop`，跨进程跳过，直到真实规则修订。保存失败，不只保存通过样品。
- 每批最多4轮；队列耗尽或遇到未知规则，产生 needs_design。不要启动无限换 Seed 的后台任务。
- 按原候选库要求记录技术候选；根 `modules/` 的正式资格仍须满足当前合同、目标回读及准入，不能由候选入库推定。视频观感、实际试玩、生产批准独立。用户视频反馈不必等到真人试玩才能驱动下一轮。

## 每次交付的指标

列出：新入库候选、独立动作家族、父家族的新适配、跨进程复用、提前拒绝、needs_design、每阶段实际用例与墙钟耗时。ID、尺寸、Seed、标题、程序候选和反复回归都不增加家族数。

先交付单 Module 的短视频、标准文档和有向端口，供 B 具体摆放后重新整图验证。可玩内容优先，通用 Macro 与整图扩展按实际请求排队。

## 条件执行示例

仅在当前授权新生产、原入口确实支持需求且已完成共用流程第4节预检后运行。示范配方不保证满足全部 Foundation 认证，输出仍须核真实格式/消费者、Route 和配置覆盖。

```sh
# 从仓库根运行；Godot/runtime 按 pcg/WORKSPACE.md 恢复。
python3 -m pcg.prototype.workshop.production_loop --name workshop-new-batch --cycles 4
# 同一原库的新进程会复用已通过需求，并跳过相同源码的失败提案。
python3 -m pcg.prototype.workshop.production_loop --name workshop-next-batch --cycles 4
# 定制队列，每项给 recipe、interfaces，可附完整 specifications 作为硬约束。
python3 -m pcg.prototype.workshop.production_loop --name workshop-map-requests --requests requests.json
```

当前注册示范只有 `refund-turnback` 与 `bell-floor-drop`，并非任意创意通用生成器。后者用于验证“地面预射击”会被提前淘汰；不是可生产内容。新增关系由 Codex 继续扩展 `production_recipes.py`、purpose 和 alternatives，然后交给同一循环，不另写新实验框架。首批结果与限制见 `docs/l4-mapgen/module-production-loop-v1.md`。
