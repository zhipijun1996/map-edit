# Module 共用工作流程

适用于既有 Module 修改/迁移、已确认设计实现和获准的新 Module 创作。本文统一执行步骤，不另立几何格式、物理系统或认证门槛。

## 1. 先确定授权和工作模式

先读当前用户要求、根 `AGENTS.md`、`MAP_FOUNDATION.md`、`MAP_GENERATION_GUIDE.md`、`pcg/WORKSPACE.md` 与 `pcg/OUTPUT-CONTRACT.md`。用户当前明确授权优先于 skill 中历史任务限制；Foundation 是模型规范，Guide 的数量、尺寸和算法是推荐。技能中的命令、历史状态和曾经的批量授权不自动开启工作。

| 模式 | 输入与允许修改 | 不能自动做的事 |
| --- | --- | --- |
| 既有修改/迁移 | 核原件、反馈、依赖与证据；最小修改并重验受影响范围。跨来源迁移按当前任务排序。 | 不把迁移当新原创；不因失败回收原件；不自行改已确认设计。 |
| 已确认设计实现 | 冻结交接清单、设计/来源 SHA、designVersion、人工意见和用户指定子集；补齐真实参数与控制策略。 | 不追随后来扩大的清单；不改设计页/人工意见；不把设计保留当技术或生产批准。 |
| 新 Module 创作 | 仅在当前授权允许时，由设计卡、真实机制与最小可玩核心开始，使用既有工坊和 Harness。 | 不因修改 skill、Guide 库规模或旧生产命令恢复暂停的批量生产；不同时扩展 Map。 |

设计讨论阶段只做用户允许的图文工作，不强行运行 Godot。用户已经要求实现、修复或验证时，在授权范围内继续执行，不额外发明逐件批准。提交、推送、发布与合并分别遵循当前授权；skill 不写永久的“不提交”，也不自行授予合并/发布权限。

执行前在现有任务记录中写清：模式、起始提交、对象与版本、允许的参数/策略范围、不得改动项、输出目录、验证目标与预算。复用现有记录格式，不要求新增一套状态系统。并行设计与实现使用独立分支/worktree，实施只绑定冻结的授权快照。

## 2. 模型与实际格式分别核对

模型以 [MAP_FOUNDATION.md](../../../../MAP_FOUNDATION.md) 为准。执行时至少核：正整数 W×H Block 完整矩形（默认128px、可配置）；外边 BoundaryBlock 边中心 Port 与内部 staging 分开；surface/初始权限合法；N×N 有向关系含自环与每格多 Route；部分连接和真实封口；同 base 的完整水平镜像；角落换边的互斥及联合配置认证。静态布局范围、运行时动态运动、合法跨边界通行分别判断，不要求动态实体永远不出矩形。

格式不能只凭文档猜测。检查当前实际导出/验证/加载路径：

| 工件 | 核对职责 |
| --- | --- |
| 设计 `pcg/module-design/v1` | 表达构图和目标；不能直接作为可玩包或技术认证。 |
| `module.mapnote.json` / `gunman-rush-level-sketch/v1` | 沿用已有内容格式与实际 `generationContract` 实现；检查 `module-contract.js`、`pcg/contract/export.py`、`pcg/migration/` 中实际调用路径。旧合同版本不自动获得新资格。 |
| cases、真实参数、runner/作者检查 | 核真实几何、动作、机关/敌人/奖励、Port 与 Route 绑定；字段存在不等于消费者执行。参数留在已有消费位置，不造第二份权威几何。 |
| manifest、源码快照、报告和媒体 | 是索引与证据，绑定 SHA、版本与覆盖范围；不以新字段或 pass 标签替代加载和真实执行。 |

字段名称和文件集随已有实现使用，不要求所有生成路径伪造迁移专用文件。迁移 CLI、schema 或消费者缺少规则时，记录具体缺口并在授权范围内补实现；不得丢字段、虚构默认值、宣称文档已有所以功能已支持。UNKNOWN 不等于无路、零成本、无要求或通过。

## 3. 两类内容工作的实际步骤

**修改已有内容/实现确认设计：** 读取原件与失败 raw → 核精确授权/设计差距 → 保留核心地貌、因果与资源关系 → 补真实参数/驱动 → 小范围实际验证 → 冻结修订 → 按影响范围认证 → 可玩包回读及证据交付。一般迁移允许的平移、接岸适配，不能覆盖已确认设计的精确约束；遇冲突反馈，不悄悄补安全台、改敌人位置或放大矩形。

**新生成：** 读取实际需求、原话、已有家族与失败 → 小量可证伪设计卡 → 核真实 Cell/能力与消费者 → 程序生成最小可玩核心 → 廉价反例及扰动小样 → 选择并冻结一个方案 → 完整认证 → 按实际需求扩展接口/配置 → 标准输出、原生加载回读与媒体。设计卡说明玩家观察/选择、动作因果、空间用途、真实资源/恢复、奖励/回程及差异；机制缺失先记录/实现，不用动作词假装支持。复用原规则、库和 Engine，不另造候选系统。

两类流程都先找可靠的真实控制方案，再消耗正式验证预算。允许修驱动和补参数；不能通过自动补弹、设置轨迹、删除危险、降低扰动/门槛或强迫唯一按键序列来救过。

## 4. 正式验证前的必做预检

以下是执行要求，不能声称现有 CLI 已自动阻止全部错误。未完成预检，先补齐，再启动正式 qualifier/full campaign。

1. **真实运行绑定。** 核官方 Godot 版本及二进制 SHA、游戏源、原件保护清单、Harness/runner/作者检查源码；使用冻结输入做实际 clean 小样。确认输入被原机制接受、参数被消费、奖励与资源变化实际发生。
2. **控制调度。** 核 DSL 的持续状态、命令触发和超时。现有 runner 中 `settle` 会持续覆盖移动轴，不能假设后续 `axis` 已取消它；dynamic 条件须接入实际调度（部分路径需有效 `state`）。请求射击不等于接受射击，等待结束不等于落稳。用 raw 中请求/接受事件、位置、接地、弹量与目标命中核对；需自适应策略时先核已有 DSL 是否支持。 零噪声的固定初相位见证与正式 `clean` 校准不同：核实际 `instantiate`，它仍会扰动移动平台/齿轮初相位和敌人初始冷却。运动周期须包含真实停靠时间，按可观测位置/相位调度，不读留出种子。删动作反例可能保留原动作的辅助字段，驱动须能安全处理缺少方向等字段的等待命令。
3. **解析实际协议。** 记录最终协议路径、SHA、schema、门槛、扰动、试次数、预算及种子/留出池绑定。迁移 `physics.run` 的默认协议由 `pool_protocols.runtime_protocol` 解析；没有 adaptation 标记可能选择旧 v1，不能凭“改过 Module”推定 full v2。显式选择符合目标的协议；已绑定独立池时使用其绑定协议，不能强制 FULL_PROTOCOL 覆盖。
4. **先算最大调用量。** 按实际 runner/协议计算各 Route 校准＋可能的留出、边界/连续入口出口、反例及其他调用，并与单件/批次预算逐项比较。例：当前 full v2，12 Route 的动态校准和留出上界是 `12×(12×3)×2=864`，还须加实际边界和反例；旧 v1 单件350预算容不下。不可只估计名义路径或指望早停省预算。 同时检查每个派生 case 的实际帧上限（包括续行增加的帧数）；总调用量合法不代表引擎会接受每个 case。预算不足时在运行前缩小可交付认证范围或提出协议工作，不能失败后提高预算或削减覆盖并称完整通过。
**连续边界夹具：** 保留原路线的全部控制、原落地目标和等待条件，在原路线完成并真实落稳后追加跨口动作；不能改写末个 `settle` 来替代原目标，否则会跳过下降落地或留下永远达不到的旧等待条件。修复夹具只追加受影响的真实边界实测与严格谱系，复用原校准/留出字节，不以重抽留出救过；保留原始失败。

**受控初态与重试：** 新 Cell 接入后逐项核对采样器的控制登记；`latches.ferry_id` 与分组启停的 `group_motion.targets` 都须匹配真实原生初态。保存受控载台的来源停位，并核对所有无关随机抽取和输入误差未变。每个 case 重置重试计数与延迟；真实重试按新请求序号生成误差，先恢复真实发枪站位。实际高度可直接成为射击触发，避免“等到高度后再开始一轮延迟”。夹具连续穿台须等待原 Motor 清除上一块平台的穿台记录。

5. **冻结与留出守卫。** 在新正式运行前执行已有 `holdout_guard` 检查，保留 sourceVersion、程序、内容及协议绑定。观察过的条件不因改名/换 seed 变新留出。还要检查中断运行中已执行的封装和未封装批次；曝光按真实执行登记，不能以缺少最终报告推断未看过留出。仅修反例驱动而未改名义动作时，核全部参数差异并保留原留出，标注同条件重放，不称新独立池。仅真实修订按工具限制冻结并登记新池；纯观测器/元数据/打包变化优先只读重分析原 raw。登记后检查实际输入和报告确实使用绑定协议；不得为修复预算误选而伪造程序变化获取新池。
6. **预先规定选择和停止。** 固定小样域、候选数、选择规则、修订次数和成本；校准未过不看该 Route 留出。不能从已见留出反复选策略或调参。超预算、零帧拒绝、执行中断各自记录，均不能冒称物理不可能。

**运行中的输入必须不可变。** 每个候选版本在独立目录冻结 Module、cases、参数和源码绑定；队列与原生包均读取该快照，不读取会被下一次修订覆盖的草稿目录。原生运行依赖按实际导入显式列举，避免目录 glob 将以后新增的无关脚本纳入旧包依赖。提交前用原生场景实际加载检查解析错误，不能把零帧拒绝当路线失败。

**反例与中断须保持原语义。** 删射击反例可能保留观察等待和辅助字段；等待没有方向时不得让旧自动重试读取不存在的 direction，也不得补回被删的射击。修复反例驱动只重验受影响的反例，沿用原校准/留出字节。引擎原生崩溃须保留原日志、输入和退出码；续跑先核冻结 SHA、协议、池、种子及逐批输入完全相同，复用完成的 raw，只执行崩溃批次或尚未执行的批次，另记重放成本，不能声称新独立留出。

留出曝光按实际已执行批次登记，不等待完整报告；中断、反例驱动报错或尚未汇总质量门槛，都不使已见条件变成未见。缺失完整报告时，先核各 holdout 批次的输入、原输出、执行退出码和协议，再登记曝光。不得因旧锁漏记而把已知输入复测宣称为新独立留出。

预检记录放现有任务/实验目录；源码冻结后不修改依赖。单次见证、扰动校准、留出、接缝、同世界返回、原生加载、严格回放与人评分别计数并声明覆盖；单 clean 成功不授予完整资格。

## 5. 变更怎样影响旧证据

| 变更 | 处理 |
| --- | --- |
| 索引、说明、纯元数据 | 保留旧工件；确认实际执行语义未变后，可校验复用。不能因改内容标签重做留出来获取新条件。 |
| 观测器/归因 | 保存旧断言、失败和源码 SHA；对原 raw 只读重算，保留无关否决；用真实正反例验证新测量。证据不足则另列 UNKNOWN。 |
| 控制程序/真实参数 | 冻结新版本，小样核接受事件与效果；重验受影响 Route、因果、资源和边界。新独立池资格由实际守卫决定。 |
| 几何、敌人/机关/奖励、Port/封口/镜像 | 先核是否获准；重验受影响方向、完整配置、净空、恢复、接缝与反例。不要全库无差别重跑，也不继承未覆盖资格。 |
| 表现或打包 | 原生加载/回放及依赖检查；若枪口、碰撞或执行发生变化，转为实际内容修订。 |

## 6. 失败归因和对用户的结论

先报事实和范围，再报假设。对每项失败保留：输入/输出与源码 SHA、首个偏离帧、请求/接受输入、状态/资源、具体断言、可复现命令、下一项区分性检查。不要只抄最终超时，它可能是早先漏命中或受伤的后果。

| 已证实的观察 | 允许的结论与后续 |
| --- | --- |
| 协议/预算误选、运行中断、缺绑定 | 验证流程无效或证据不完整；保留 raw。不是 Module 物理失败，也不能追认认证。 |
| 观测器锚点/因果绑定错误 | 测量问题；窄范围修正并重分析，不能删除真实伤害或奖励否决。 |
| 固定控制在扰动/敌人相位下失误 | 该策略在所测条件下未达门槛；先核控制调度、瞄准、资源恢复和等待策略。不能推出玩家无法通过或设计不可实现。 |
| 字段无消费者/运行时未接入 | 工具或实现缺口，继续在授权范围内修复；不能归为设计物理不可能。 |
| 实测或静态约束表明确认设计与要求冲突 | 列出精确版本、约束和证据，反馈设计冲突；不自行改变设计。有限搜索失败仅支持“尚未找到合格方案”，不证明无解。 |

反例把射击删为等待后，自动重试必须检查上一项仍为真实射击且包含必要方向，不能补回已删动作。缺字段等待只观察机关状态。若驱动报错，保留失败批次；同输入续测须逐项核对原输入、池、种子、完整批次 SHA 和实际新驱动命令，并单独绑定修复源码，不能把新驱动冒称为原驱动。

没有充分因果证据时写“原因待定/策略未达标”。质量失败如实保留，修 skills 不改变任何历史结果。技术认证、AI分析、人工观感、实际试玩与生产认可始终分开。

## 7. 交付与复用

交付精确来源/设计/实现版本、修改范围、参数及控制策略、格式/加载结果、各 Route/配置的 PASS/FAIL/UNKNOWN/NOT_RUN、原始成功失败、协议/预算/留出记录、复现命令、可玩样品和视频。遵守 [物理 skill](../../pcg-physics-contract/SKILL.md) 与 [视频 skill](../../pcg-video-review/SKILL.md)。候选库记录不等于根 `modules/` 的正式认证；正式目标回读、引用与可恢复归档完成后才处理原件，不因失败自动回收。暂停的工作不因交付或新一轮会话自动恢复。

启用 sparse-checkout 的工作区，目录级 `git add` 不保证 ZIP、影片、归档分片已入 Git 树。用限定交付路径的 `git add --sparse`，再逐个核对 `git ls-tree` 与匿名下载 SHA；不要为收附件把无关工作区文件一起提交。
