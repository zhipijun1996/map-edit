# 真实物理认证与地基迁移

适用：既有 Module 修改/迁移、已确认设计实现、获准新生成内容的动作与机关验证、认证失效分析、接缝及连续路线验证。它不负责在线 Map 求解，也不维护另一套物理。

先读 [MAP_FOUNDATION.md](../../../MAP_FOUNDATION.md)（强制契约）、[MAP_GENERATION_GUIDE.md](../../../MAP_GENERATION_GUIDE.md)（推荐方案）、[迁移状态](../../../pcg/migration/foundation-v1/status.json)及[Module迁移skill](../pcg-module-migration/SKILL.md)。项目规则冲突时按基础文档解释，指南的数量和尺寸推荐不能冒充强制门槛。

开始前按[Module 共用工作流程](../pcg-module-factory/references/module-workflow.md)确定工作模式、精确授权、实际格式/消费者、控制调度、最终协议与预算。新生成是否暂停、迁移顺序和提交权限由当前任务决定；本 skill 不自动恢复生产或开启 Map 工作。旧素材、失败、认证和历史身份保留，工具缺口不以字段默认值补成通过。迁移时目标回读、引用和可恢复归档完成后才处理原件；新生成没有旧件归档义务。

## 1. 明确认证对象

每份证据至少绑定下列身份，字段名可沿用实际仓库格式，语义不能省略：

- 基础模板 `base_module_id`、内容版本、源提交/文件 SHA、Foundation 版本。
- 整数 Block 宽高、Block 像素尺寸、原向或 `mirror_x` 方向。
- Port 定义及初始权限、被测 route ID 和有序起止 Port；同一对可有多条 Route。
- 本次实际连接 Port 子集 `connected_port_subset` 与所有未连接 Port 的 `closure_profile` 版本及几何。
- 初始机关配置、能力集合、离线进入/离开合同、策略版本、固定预算及校准/留出种子。
- 引擎二进制 SHA、游戏源绑定、原 Harness/runner、原输入、完整 raw、成功与失败记录。

认证单元是“版本＋方向＋Route＋连接子集/封口组合＋初始条件及动作合同”，不是一个笼统的 Module pass。接缝另绑两侧模板/方向/Port/封口配置及试件版本。一次见证只证明它覆盖的条件；模块单向通过不授予反向、镜像、连续玩法或整图资格。

## 2. 先检矩形与真实 Port

Module 占据完整 `W×H` Block 矩形，W/H 为正整数；不能再将稀疏 owned cells、不规则占用、外邻借地或像素包围盒直接当作新地基的合法占用。内部地貌仍可不规则，矩形不要求画成房间边框。实例之间必须矩形不重叠；共享 Port 边界点不产生共占 Block。

分别记录三种判断，不要合并成一个“越界”失败：

1. **静态布局约束**：所属 Cell 的布局几何、环境碰撞及封口布置在 Module 矩形内；环境机关的认证碰撞/运动范围也要按其布局合同检查，不能靠扩大保留区掩盖冲突。
2. **运行时运动**：玩家、敌人及弹丸按真实机制运动。敌人 AI 走出原矩形或弹丸飞出边缘不等于两个 Module 的矩形占用重叠，不因这一点直接判静态布局非法。
3. **通路范围与边界接口**：玩家实际跨模块通行必须经合法 Port。依赖未连接开口、外部支撑或未知邻区才能完成的轨迹，不能认证为内部独立 Route；保留真实观察并报告外部依赖或未认证通路，不能删除轨迹或改称矩形重叠。

Port 必须位于外缘 Boundary Block 的外侧边中心，具有稳定 ID、`LEFT/RIGHT/TOP/BOTTOM` 朝向、地貌类型与初始 `INPUT/OUTPUT/INOUT` 权限。优先用双倍整数 Block 边界坐标核对：左 `(2x,2y+1)`、右 `(2x+2,2y+1)`、上 `(2x+1,2y)`、下 `(2x+1,2y+2)`。内部 staging/dock、goal 矩形、Harness 虚拟 marker 只能辅助测量，不是实际 Port。

| 地貌 | 物理条件与方向限制 |
| --- | --- |
| `AIR` | 无安全站立支撑，按预认证的向下进入情形验证；底边不能具有 INPUT 权限，包括 INOUT 的进入部分。顶部 AIR OUTPUT 没有合法底边同类 INPUT 可配，不作为必须连接的有效向上出口。 |
| `ROCK` | 下方真实安全实体岩体支撑，仅 LEFT/RIGHT。 |
| `ONE_WAY_PLATFORM` | 下方真实安全可穿平台支撑，可用于四侧，逐方向验证实际穿越与落稳。 |

接缝必须坐标完全重合、外法线相反、同地貌类型且初始权限相容；不得自动变换类型、补平台、传送、补枪或恢复精力。到达权限不等于离开权限；门运行后打开可能改变实际行为，但不反写初始权限。

## 3. 建立全部有向 Route 与封口覆盖

对 N 个真实 Port 建立完整 `N×N` 清单，包含对角线。每格允许多条 Route；`A→B` 不推导 `B→A`。没有验证的关系保留 UNKNOWN/未认证；有限失败不能证明无路，也不能把未搜索格标成物理不可能。

`A→A` 自环可以表达同口进入、取奖、同口返回，必须使用同一个真实边界 Port，并满足进入和离开的初始权限，通常为 INOUT。内部两个虚拟 marker 或无边界接口的“离开再回来”控制不能充当 Port 自环认证。

每条 Route 保留基础文档要求的位移、必要能力、动作标签、难度、时长、资源描述、初始条件、进入/离开条件和 validation。逐条核对玩家实际观察/决定、动作对世界的影响、奖励取得、失败恢复以及替代解。多条策略或动作词变化不自动成为新玩法家族。

允许只连接部分 Port。所有其余 Port 必须用 Module 内天然封闭地形或已认证局部封口 Cell 处理：

- 封口真实阻挡越界或可靠终止通行；仅扣血、能硬穿的荆棘和视觉墙都不算合格。
- 检查单封口与同时封口的相互作用，不破坏本次必要 Route，不产生未声明合法连接。
- 连接子集、封口 profile 及影响后的实际 Route 集合共同入证；不能将全开模板 pass 无条件复用到封口变体。
- 可复用局部封口和组合证明以明确的覆盖声明复用，不要求在线枚举全部 `2^N` 子集；未覆盖组合不可选。

规划只列部分 Route，不能删除真实额外 Route。反例或试玩发现额外通路时记录其起止、能力、初始条件、封口依赖和证据，认证后纳入实际图；尚未认证的真实观察是待处理缺口，不能只因不符合动作词或计划路线而屏蔽。

## 4. 真实 Godot 实验

复用已有 `WorkshopEngine` / factory 引擎、原 Actor、原资源组件与现有 Harness。核对精确 Godot 版本/二进制、游戏源提交、保护原件清单及 runner 源；已存在 870 保护原件的基线仍需核验，不能把历史数量当新基线证明。禁止轨迹直接赋值、测试中补资源、删除危险或未校准的平行模拟。

先执行共用流程第4节预检，保存实际协议路径/SHA、完整调用量上界与留出绑定。迁移协议默认值不等于 full v2；已登记独立池须使用绑定协议。预算不足在运行前处理，不事后提高预算。先固定实验预算、几何/策略选择规则、动态相位、瞄准与操作扰动、反例范围及独立留出条件。按原质量门槛筛选，失败保留；不得从留出挑策略或降低门槛救过。定义拒绝的0帧输入、真实步进、元数据预检与原生录像调用分开计数，不以预检代替动作实验。

新增或改接 Cell 后，先核采样器是否识别真实控制关系。原生风铃控制载台与分组启停载台都应按其声明的初始停位采样，运行相位由真实输入改变；不受控载台、齿轮和敌人冷却按协议扰动。登记遗漏属于验证流程问题。用原生绑定、来源停位及同条件诊断证明后，冻结版本化修正，保留原无效运行；所有无关 RNG 抽取、误差、门槛及种子保持原样。历史报告继续按各自采样策略核验，不能批量重标旧证据。

连续夹具须尊重原生动作锁与穿台记录。落到下一块可穿平台后，确认前次穿台已经结束，再请求穿越；使用正常输入等待并保存接受事件。自动重试须在每个 case 重置状态、按实际请求序号施加误差，并在当前真实支撑/瞄准站位满足后发枪。删动作反例中的等待不得触发被删动作。真实参数或控制改变仍按对应范围重验。

最小验证范围：

1. **动作和因果**：真实枪口、弹丸飞行/命中、反冲、承载、惯性、碰撞和机关碰撞状态符合声明。目标瞄准仍叠加独立误差；改变目标必须重算飞行与运动关系。
2. **完整身体**：使用真实角色碰撞形状与适用的扫掠/接触，检查净空、门通过时间、防夹及危险接触；不只检查中心点或单帧位置。
3. **资源和进入/离开**：实际输入前采 entry snapshot；post-action 第0帧不是进入快照。核能力门控、生命/伤害、精力、弹药、次数、冷却和真实恢复；observedExit 只说明实际出口，不授予任意离开状态保证。
4. **恢复和连续性**：漏落点、错过机关、延迟离开、重新关闭等按声明测试。真正返回需同世界不重建、不重置资源/敌人/机关；fresh 反向满资源样品与去程后回程分开。settle 或固定等待不等于到达，续接按真实位置和接地判断。
5. **有限反例**：普通跳、零枪/省略关键动作、地面预开、越顶、底绕、不同落点、低成本奖励和封口突破；保留合理合法替代，不强迫唯一按键序列。未找到绕法不证明必要性或不可达。
6. **相位与留出**：动态机关相位、操作时机和瞄准扰动按预注册范围覆盖，独立留出不调参。12/12 等有限样本不是人类通关率100%。

按 target_id 区分敌人伤害与玩家伤害；空中命中回充必须有实际空中命中和资源增长共同证据，不能把落地回充冒充命中回充。拆除/生命周期修复单独保留真实回归证据，不计新内容或新玩法成功。

## 5. 镜像与接缝认证

水平镜像属于同一 base 模板的方向变体，不增加基础模板数。镜像必须覆盖全部地形、碰撞、Port、机关、射线/行为方向和视觉：Block `x'=W−1−x`，双倍边界坐标 `u'=2W−u`，LEFT/RIGHT 交换，水平动作/位移取反。Port ID 可保持，初始 INPUT/OUTPUT/INOUT 语义保持；Route 矩阵不转置，不能将正向成功偷换为逆向成功。

只启用经过离线认证的方向；原向证据不能自动授予镜像。封口组合也随方向变换并验证。纯对称可按明确等价证明合并方向索引，不能仅凭截图宣布等价。

必要接缝试件真实实例化两侧原 Cell 并验证接口运动条件、连续支撑与资源承接；不补接缝地形或恢复资源。相邻端点坐标相同不等于动作连续。单 Module、接缝与连续挑战证据分别绑定，均不能替代 B 的整图验证。

## 6. 离线与在线边界、交付

生命、能量、精力、速度、装备和机关过程由真实 Godot 在离线验证及运行时负责。资源画像、初始条件及进入/离开要求是离线 Route 合同/静态评分资料。在线 Map 只接收生成开始时的能力集合，按静态必要能力与初始权限过滤；不要求在线逐步追踪 HP、速度、资源或开门状态，不将 offline trace 变成在线状态搜索。

初始图必需通路不能偷用开门后才出现的连接。依赖开门返回的玩法须以已离线认证的完整特殊结构表达，不能让通用静态求解假装门已开。

交付绑定原件的技术结果、完整 Route 清单、方向与封口覆盖、有限反例、失败和 UNKNOWN；视频按[pcg-video-review](../pcg-video-review/SKILL.md)处理。技术认证、AI审阅、人工视频观感、亲自试玩和生产认可分别记录。

迁移时继续复用已有标准输出与 Harness，参照 [OUTPUT-CONTRACT.md](../../../pcg/OUTPUT-CONTRACT.md)，但旧 schema/validator 若尚不支持矩形、真实 Port 类型/权限、对角自环、镜像或 closure profile，明确列出阻塞字段与受影响认证，不改旧证据标签、不声称已适配。格式转换结果标为待重验；只有对应实现及离线实证完成，才能成为新地基可用认证。

## 四角Port换边的物理认证

采用[角落Port扩展](../../../docs/l4-mapgen/corner-port-relocation-v1.md)。同角落Block相邻边中心是待认证接口配置，不能由坐标合法推断可达。局部支撑/表面/封口有改动时复用原Harness，检查真实24×36身体、合法surface/初始权限、相关原有向Route、回程/恢复、新口接缝和廉价绕行；新v2按用户规则保留旧开口几何，不将旧口闭合当准入条件，Map另验相邻空间影响。ROCK不得直接转为上下口，底部AIR不可进入。每份证据绑定基础内容版本和完整配置SHA；组合、镜像和封口兼容须分别有对应实证。未测UNKNOWN，有限反例不证明不存在旁路；可选配置失败不否定原配置资格。

## 反例成本与实际因果归因

不能因多开一枪、多跳一次就通用覆盖原反例否决。额外按键数不证明实际资源、风险或路线成本；记录真实空中弹量、地面回充、命中恢复、精力、冷却、受伤与时长。只沿用已有明确家族/目标例外，不把原本只适用于特定承载驻停目标的例外扩大到全部内容。

也不能把“第一枪”与“完成核心关系的那一枪”混为一谈。初步空枪、撞岩壁的弹丸或早已过期的开门，不自动推翻稍后真实发生的空中射铃—反冲—有效窗口穿门。发生此类观测歧义时，保留完整原始trace、原因果检查与原始严格分类；用唯一实际弹丸命中、对应机关开启次数/窗口、当时人物姿态、完整身体通过时间及恢复落点建立窄范围证据。不得过滤掉不利事件、剪掉首段trace或凭标题/动作次数放行。

确属观测器归因问题时，新建有原断言源码SHA和内容版本绑定的测量修订，复用真实Harness与原门槛，保留所有无关的奖励、刹车、返回、资源和安全否决。冻结过的旧观测器/作者/报告不覆盖；新绑定经过实际正例与缺核心动作、过期窗口、错误弹丸等负例后重绑证据。未能建立因果证据的保持待修，不借修观测器降低玩法要求。相关实证见 `pcg/migration/foundation-v1/counter-original-policy-raw-audit-v1.json`。

正式qualifier/full_campaign使用 `pcg.migration.holdout_guard` 保留已见条件锁。改名、换Route标签或只换seed不产生新独立留出；纯测量/打包修订优先原raw只读重分析，不重挑留出。原生coin/note等目标必须同一pickup ID有原消费者`accepted`事件及实际amount/钱包状态证据，到出口但漏取必需物不能算同一外部结果。
