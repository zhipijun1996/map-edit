## 当前图文创作入口（优先于以下历史迁移模式）

用户已授权创意→示意图→人工审核→待实现→实现后归档的工作方式。应用[Module工坊流程](../../../docs/module-workshop.md)，入口`generation/module-workshop/`。本会话可以接收人工或用当前Codex大模型提出创意并画图，不因旧文MIGRATION模式阻止已授权的图文工作；真实Module生产、物理与旧批量任务仍不自动恢复。

用户最新明确“ai出创意直接出图。我看文字不太能审核”。后续AI创意在同一轮完成去重、Cell支持判断、图文设计与工坊发布，默认每批5份；文字提案只作内部中间记录，不能作为独立交付后再等待用户要求出图。图上直接标清Block/Port、人物与弹丸路径、关键前后状态及缺Cell；缺口不妨碍设计审阅，也不表示已实现。用户明确只要文字时再按其要求调整。人工原话和AI推导分开保存；所有新图仍须逐版本人工保留才进入实施交接。

先读现有Module工坊索引和真实Cell/原失败，检查体验重复与功能支持。原话、解释、模型来源分开，记录稳定ID；用`tools/module_workshop.py intake/attach-design`和原示意图渲染器逐版发布。人工保留必须来自聊天真实反馈并绑定当前designVersion/SHA，`record-decision`仅进入原implementation-handoff。图文改动不继承旧技术通过；不支持的想法返回Cell/规则缺口，不能替换普通房间。实现会话按现有物理/工厂/迁移合同验证，并用原实现回执返回；只有真实主库及版本/哈希匹配才能显示归档。

网页AI按钮只准备供当前会话的大模型请求，不是在线模型调用。网页创意与意见是本机草稿，复制回聊天前不视作已收到或人工批准。模型去重比较决定、因果、空间/资源/风险和不同来向，镜像/尺寸/装饰/多口数量不增加家族数；去重和缺口要写在图稿/创意记录中。

最新HQ03反馈要求禁行意图用已有边界地刺表达，不能画不存在的整块危险区Cell。优先引用真实`PlatformThornDefinition`的支撑面、朝向、边沿偏移与长度；图中地刺须依附实际岩体/平台。伤害不等于不可穿越，更不等于合法边界封口；完整身体、受伤无敌绕行和实际Route仍待实测。HQ05已认可的是受击固定方向炮台版，旧镜面原文只作来源；炮台Cell仍缺，后续适配不得冒称已有实现。

HQ第三轮反馈见`feedback/module-workshop/review-receipts/hq-feedback-003.json`：HQ06因可直接射铃使炮台冗余而废弃；HQ10因普通三口加一次射铃未改变实际路线选择而废弃。后续先比较省略中继机关、直接作用于最终目标、固定几何替代开关的方案，不能把增加操作步骤当作玩法价值。未排除的低成本替代要明示；本轮不借此复活两个废案。HQ09改为竖板只挡弹、不承载人物，必须明确缺碰撞筛选Cell，不能沿用原生实体载台的支持状态或旧落点取舍说明。

HQ第四轮取消全宽门，采用击铃收回出口台上下尖刺、平台本体保留的方案。不可用单Module静止入口掩盖邻接模块带速跳入；上下/侧绕、穿伤无敌帧和真实接口状态要单列。危险接岸在收刺前并非安全可穿Port，不能继承普通平台的认证或把伤害当硬封口。尖刺几何已有、同组收回控制仍缺，设计与实现资格分开。

后续提案先读取已收人工筛选反馈，当前见`feedback/module-workshop/review-receipts/interface-feedback-001.json`：S01因已有相同内容被废弃，双靶续枪上升优先复用既有身份，不靠接口/尺寸重复立案。S13保留“奖励后换门”的机制假设，但该设计已废弃；奖励袋必须有可说明的观察、选择、动作挑战或成本，简单走流程不自动值得宝箱。“想法挺好”只作机制兴趣记录，不能复活废弃设计或授予新版本认可。

当前实施采用最新已授权迁移顺序与三去向：先本仓库、后主游戏；技术合格可复用内容入根 `modules/`，事实已确认的完全重复非代表项/明确排除项入 `modules-recycle/`，近似待审、缺口或验证失败留原处。目标验证与回读、引用及可恢复归档检查完成后才归档原件，不提前搬走失败源。技术认证与人工观感/试玩/生产认可分开；旧Map生成器退役，本轮不实现新Map、不commit、不发布。工具能力以实际实现和回执为准。

## 内容与接口采用的新模型

- **Module 占用是完整矩形**：宽高为正整数 Block，实例原点为整数 Block 坐标，实例矩形互不重叠。默认 Block128，可配置；Cell 保留像素级地貌与碰撞，不按 Block 缩放。内部地貌可以不规则，Module 占用不能用凹形掩码替代矩形；画面无需实体外边框。
- **空间约束按实体职责区分**：Cell 静态布局、环境碰撞与边界封口在所属矩形内；运行中的玩家、敌人、弹丸移动不作为 Module 矩形占用重叠。真实动态行为及接口仍按离线契约验证，不能沿用“所有动态角色/弹丸永不出格”作为通用定义。
- **Port 在矩形外边界 Block 的外侧边中心**，方向为 `LEFT / RIGHT / TOP / BOTTOM`。连接要求世界边中心重合、法线相反、地貌同类、初始通行权限兼容、接缝经过认证。内部 staging 与边界锚点分别记录；不把身体站位当锚点，也不沿用凹边界 Port。
- **三种地貌类型不可混接**：`ROCK` 有安全实体支撑且只在左右边；`ONE_WAY_PLATFORM` 有安全可穿平台支撑，可在四边；`AIR` 没有安全站立地面，按预认证向下运动进入，不能有底边 AIR Input。顶部 AIR Output 没有合法同类相邻 Input，不能冒充必接向上出口。
- **初始权限独立于运行中开关**：每口声明 `INPUT / OUTPUT / INOUT`。初始单向门只提供初始允许方向；开门后可能双向是运行时事实，不预借给初始图。方向未验证保持 UNKNOWN，不把未知反向叫已证单向。
- **Port 允许部分连接**：实例只启用实际需要的口，其他口必须采用模板已有封闭地形或经过离线认证的局部封口 Cell。封口在本 Module 内，确实阻止无效越界；仅扣血、仍可穿出的荆棘不是有效封口。封口不能破坏本次必要 Route 或产生未声明连接；有相互影响的组合要有明确兼容模式。不能再要求 incident 数恰好等于模板全部 Port 数。
- **Route 是 `N×N` 有向矩阵**：包括对角线，每格允许0条或多条实际 Route。允许同口进入、取奖、同口返回的自环，相关 Port 仍需兼容进入/离开权限。正反向独立，不默认全互通；UNKNOWN 不等于已认证空集。
- **保留全部实际 Route**：规划所选路线不删除其他真实通路。所有真正接通、能力允许、与封口兼容的实际 Route 都进入实际图，包括反例发现的绕行、捷径与自环。通向封口的口没有外部连接边；封口若改变内部 Route，须按认证配置反映真实结果。
- **基础模板与镜像方向分开**：一个 `base_module_id` 仍是一个模板；原向与水平镜像最多是两个方向变体。镜像覆盖全部 Cell、Port、碰撞、机关、方向参数与视觉；权限语义不交换，Route 逻辑起止 ID 可以保持，矩阵不转置。只使用已认证方向，不把镜像或新版本重复计为新模板/新玩法家族。

这些是迁移目标。若当前 schema 仍拒绝自环、缺少地貌/权限/封口字段，或消费者只支持旧几何，记录具体迁移缺口并协调修改与重验；不能靠改标签、伪写自口终点、丢字段、默认为全连接或恢复旧接口来宣称支持。

## 离线创作与在线生成的分工

大模型只参与**离线**解释、设计、源码审查、迁移修订与反馈分析。几何搜索和验证由程序及原真实 Godot Harness 执行；复用现有候选库、源绑定、质量档案及反馈机制，不建第二物理、候选库或 Map Generator。

在线是纯程序：读取 Seed、区域配置、库版本及**生成开始时一次输入的静态能力集合**，按 `required_abilities ⊆ available_abilities` 过滤认证 Route，并采用初始 Port 权限。可静态使用动作、难度、时长、资源画像做评分，**不逐步追踪**速度、精力、能量、血量、装备、背包或机关开启过程，不在线调用 LLM、不临时补 Module。

离线 Route 必须保留真实资源、进入/离开运动、机关初态及恢复记录；这不意味着在线要传播玩家资源状态。依赖开门后才能返回的特殊谜题，要作为完整特殊结构离线认证并明确边界，不能让通用静态图预先当门已开。Module 内部路线由本工坊负责，区域路线组织与整图布局由 Map 任务负责。

## 迁移时保留来源与体验

为每个既有对象建立可追溯的基础身份和迁移记录：原游戏/生成来源、原 ID 与版本、实际场景/源码 SHA、已有证据、原向/镜像归属、原 Port/Route 与新字段对应、缺项、修订理由、失败及下一步。历史物理通过不自动成为新地基认证；旧原件不覆盖、不重标。

人工创意保留稳定 ID、`source_type=human_idea` 和逐字原话；解释与设计假设单独保存，关联提案、规则、候选版本与实验。人工提出或总体正向评价不等于批准某条 Route、镜像、封口、趣味或生产准入。

迁移修订至少回答：玩家观察什么、在哪里决定；人物动作与世界变化的因果；所需真实 Cell/能力/资源；哪块地貌让关系成立；奖励怎样看见/取得；失误后怎样恢复；不同进入方向和回程有何不同；哪些便宜解法会改变原意。保留本来有用的非对称来向，不强制所有输入到同一 M 或所有口互通；也不把恢复地面改名成分叉出口。

状态分别记录：迁移分析、已存在可执行规则、缺 Cell/生成/合同/消费者支持、待验 Route、技术认证范围、模型观感、人工视频意见、实际试玩与生产认可。`implemented=true`、名称匹配、示意图或技能文字都不能证明实现；缺失功能返回具体条件和可协商范围，不悄悄换成普通平台。

## 实证与成功反例反馈

1. 先读本内容的旧失败、人工反馈、源码和原始轨迹。复用真实玩家、弹丸、承载、碰撞、资源恢复和生命周期，不能由中心点/指定动作词替代身体与目标验证。
2. 迁移前固定请求、质量标准、预算、候选选择与独立留出。新几何、Port 类型/权限、镜像、封口、机关、奖励语义或策略改变后冻结新版本，按影响范围重验；不在失败后降标准或丢恢复要求。
3. 反例比较相同外在目标与真实成本。提前开门、射空、普通跳、不同落点、少枪或从另一入口绕行，凡真实可行都先作为 **Route 发现** 保存。可能推翻“必须某动作”的创意假设，却不因此变成非法通路。更便宜的安全路线不能只因没过指定 M/没切门而拒绝。
4. 发现成功替代路线时，保留原失败分类和来源，另记真实方向、条件、动作/资源、轨迹与成本；进入待认证集合。补认证后加入对应矩阵格及实际图。未认证的实际通路不能故意不记来保规划；若影响地图完整性而尚无认证，相关配置保持迁移未完成，不供在线正式使用。有限反例没找到绕法不等于证明没有。
5. 区分技术失效与体验冗余：碰撞/能力/出口/封口认证失实按证据撤回相应资格，保留原件；动作并非必要、画面无聊或与别案重复，用设计反馈/候选筛选记录，不自动抹去真实 Route 或冒称物理失败。新语义请求不能倒改旧失败为成功。
6. 评估平台/机关冗余时，先用同目标对照、省略/绕行、真实承载与恢复证据确认用途。不要看到 nominal 未接触就删平台；先检查其他 Route、失败恢复、封口、镜像与接缝依赖。删除是新内容版本，重新绑定并验证受影响范围。
7. 输出可复现命令、源快照/哈希、原始成功失败、校准/留出/反例、认证 Port/Route/镜像/封口范围及标准可玩资源。使用原严格录像比较，差异保留，review-only 不冒充 exact。短视频优先便于下载和聊天反馈，不强制用户逐件试玩批准。

## 去重、计数与交接

分别统计基础原创模板、镜像方向变体、内容版本、认证 Route、用途签名、迁移完成数及玩法家族；同一个基础模板的镜像、新版本、三/四口使用方式或多条路线不能相互乘算为原创数。旧库数量先做身份与镜像审计，不把候选版本数当基础模板数；迁移及修复不计新原创家族。

AI 去重比较实际玩家判断、因果、空间展开、路线/风险收益及资源画像。标题、Seed、装饰、尺寸、动作词、额外危险不自动增加家族。将代表、有效适配、冗余变体、待查分开，保留全部原件与技术资格；已有人工“走路无聊”反馈必须反哺审查，不能靠数量或端口数抵消。

技术认证、AI 趣味判断、人工视频认可、实际试玩与生产准入彼此独立。没有真实人评保持 UNKNOWN；也不为迁移审计/实现/技术验证额外发明逐件批准流程。交给 Map 的是实际能力/初始权限/Route/镜像/封口认证与局限，不是“单模块通过即可整图用”的结论。

## 用户恢复新内容生产后的离线循环

在迁移已具备可用基础且用户恢复生产后：读取实际 Map 缺口与人类原话 → 模型提出少量因果/空间假设 → 对照原库去重与 Cell/规则能力 → 用程序生成一份最小可玩核心并主动反驳 → 原 Godot 完整认证 → 扩展实际需要的接口、镜像及封口组合 → 持久化编译/检索复用 → 批次 AI 去重和人工审阅 → 失败反馈到下一轮。

创意记录实际调用者身份和提示/响应；未暴露模型修订就写未知，未调用外部模型就不能称在线 AI 创作服务或训练成果。规则耗尽返回 `needs_design`，不能换 Seed/换标题持续重复。恢复后的产量目标、预算及标准须另有当前授权和配置；Guide 推荐规模不触发自动扩库。
